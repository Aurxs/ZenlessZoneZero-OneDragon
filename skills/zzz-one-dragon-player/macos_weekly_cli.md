# Mac 周活 CLI：待实机验证

仅在已获本周执行授权且按上海时间为周一时运行；其他日期只检查配置与入口。先满足日活参考中的单执行、权限、资源和结果核对条件。正常任务只走 CLI，阻断诊断后仍回到 CLI。

## 当前可用的预览语法

在项目根和现有 `.venv` 中运行：

```shell
PYTHONDONTWRITEBYTECODE=1 PYTHONPATH=src .venv/bin/python -B -m zzz_od.macos.cli --dry-run --app lost_void
PYTHONDONTWRITEBYTECODE=1 PYTHONPATH=src .venv/bin/python -B -m zzz_od.macos.cli --dry-run --app notorious_hunt
PYTHONDONTWRITEBYTECODE=1 PYTHONPATH=src .venv/bin/python -B -m zzz_od.macos.cli --dry-run --app intel_board
```

三条预览在 2026-10-29 本机通过；没有执行三项周活。CLI 返回的能力描述引用了历史迁移验收，不等于这台 Mac mini 本次完整运行通过。

## 周一执行前

- 读取当前周记录、组开关与各任务配置。三项任务在当前每日组中关闭；不要为了周一任务把它们永久混入每日组。
- 沿用迷失之地的活性、战略、编队、悬赏目标和每天上限；沿用 Boss 目标、难度、编队和免费次数；沿用情报板配置和零电量战斗范围。不根据过去记录推断本周已经完成。
- 对照当前上海日期与游戏刷新周期核对记录。不清零周次数，不伪造日期，不增加试跑来消耗周奖励。
- 单任务入口的跳过语义与整组不同。先确认任务自身如何识别本周已完成、部分完成和奖励已领取；结论不明确时先报告，不能盲目重跑。

## 下次实际验收

取得授权且条件满足后，逐项用 `--app lost_void`、`--app notorious_hunt`、`--app intel_board` 执行，顺序执行且每项结束后核验。这里只固定已有参数形式，不能把尚未实测的串行组合称为已验证流程。

| 任务 | 需要补齐的证据 |
| --- | --- |
| 迷失之地 | 本周悬赏前态、真实通关与积分/奖励变化、任务实际结束、已完成再运行的安全跳过。 |
| Boss | 配置目标与免费剩余次数、每场胜利及奖励扣次、免费次数用尽后不转成耗电或无报酬刷本。 |
| 情报板 | 本周贡献前态与1000周期完成、只做零电量战斗、不接剧情、完成后安全跳过。 |

发生中断时先核对实际奖励/扣次，再决定恢复方式。不能因日志缺末尾就从头消耗一次。结果不明、验证码、登录或安全权限一律停止。

实际完成后，把命令、时间、前后态、成功或失败、断点恢复与防重复验证补入本参考；若只做了部分恢复，分别记录，不能写成从头连续通过。将实测流程与待验证项保持分开。
