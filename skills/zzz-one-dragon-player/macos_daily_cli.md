在 Mac mini 的现有项目根运行。当前部署路径为 `/Users/aurxsmax/Program/ZenlessZoneZero-OneDragon`；移动项目后重新核对，不能照抄旧绝对路径。复用项目的 arm64 Python 3.11、`.venv`、模型和当前账户，不运行依赖升级或重新部署。

读取当前账户组和任务配置，再看预览，保持用户的目标、编队、策略和次数。预览不初始化模型、连接设备或保证资源充足。默认运行原组；单项恢复可用 `--app APP_ID`，但单项调用不保证跳过完成记录，须先核对实际结果。

## 运行前

1. 读取项目 `AGENTS.md`。核对当前账户平台、每日组启用项、体力计划、补电设置及本次资源授权；不输出账号凭据或通知配置。
2. 检查同机任务/执行会话是否仍在运行，并通过可用的受支持状态查询确认输入占用。未知占用时停止；不并行启动 GUI、CLI 或联调桥。进程查询被拒时不换途径绕过。
3. 用原 OJD 路径只读检查状态。需要探测时使用项目已有 `tools/macos/gamepad_probe.py --ojd PATH`，不加 `--action`。`Stopped` 只说明服务未运行；配置允许的自动启动由原 CLI 负责。
4. 保存当前任务组、计划和相关运行记录的前态或哈希。记录上海时间与游戏周期；不手动修改日期、完成状态或计数来强迫重跑。

本任务只允许既有普通日活与自然体力。补电配置必须关闭；不消耗以太电池、储蓄电量等储备，不用菲林买体力，不充值、抽卡或购买通行证。电量不足时保留未完成计划并报告。任务授权改变时以最新明确范围为准。

## 执行与结果

- 保存 CLI 标准输出、标准错误、退出码及本次起止时间。使用管道保存日志时保留原命令退出码。
- 不用 GUI 或 Computer Use 完成日活；只有 CLI 实际阻断时，才用 Computer Use 观察或诊断，修复后回到 CLI。不得用手动切模式或领取奖励来冒充 CLI 成功。
- 同时核对终态 JSON、各启用项运行记录、任务节点和实际资源/奖励证据。`success: true`、退出码 0、`failed_apps: []` 是程序成功条件；它们不能单独证明日活已满或领到指定奖励。
- 记录完成、已完成跳过、资源不足、失败、结果不明分别对应哪些任务。日活达成需要实际活跃度与领取状态证据，不能只看“全部结束”。
- `run_status` 的 0/1/2/3 分别是待运行/成功/失败/运行中。3 也可能是中断遗留，交叉核对当前会话和日志进展后决定是否恢复。

## 阻断与恢复

| 现象 | 判断与下一步 |
| --- | --- |
| `NOT_STARTED` 且采集状态 3 | 属于未取到有效画面的初始化失败；保留日志，确认实际窗口/桌面状态。只有新证据说明窗口已加载、且确认没有任务或资源动作，才有限重试。不能忽略帧保护、使用旧画面或无限重试。 |
| `当前进程缺少辅助功能或事件投递权限，未发送启动点击` | 停止游戏执行并报告给用户。OJD 或 GUI 已授权不能证明 CLI 进程获授权；不改系统权限、不改 TCC、不通过另一个已授权宿主绕过。本人完成正确宿主授权后，先重新预检，再恢复 CLI。 |
| 登录、验证码、协议或系统安全权限 | 停止并报告具体目标与原因，保留当前状态；不自行通过验证或接受协议。 |
| 任务报错但资源结果不明 | 先查原记录、日志和实际领取/扣电结果；不直接重发带副作用动作。确定未执行或任务自身确认可跳过后再恢复。 |
| 相关代码缺陷 | 按项目调试方法定位，做最小修复及必要聚焦检查；不得削弱输入、资源或未知页面保护。保留用户已有工作。 |

整组恢复优先沿原组的完成跳过机制；单任务恢复先检查该任务的幂等行为。停止后等待原 Operation 收尾并确认输入、采集已释放。关闭自己启动的游戏/一条龙窗口，保留用户原有应用与标签；只在确认没有其他连接时，停止本轮额外启动的 OJD 服务。
