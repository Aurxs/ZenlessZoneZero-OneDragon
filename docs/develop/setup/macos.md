# macOS 部署与 PlayCover 设置

适用于 Apple Silicon Mac、PlayCover iOS 客户端和一条龙原生手柄路径。已有可运行环境可直接核对配置，无需重装。

## 1. 安装 PlayCover 和游戏

1. 按 [PlayCover 官方说明](https://docs.playcover.io/getting_started/download_playcover.html) 安装 PlayCover。
2. 准备《绝区零》已解密的 iOS `.ipa`，拖入 PlayCover App 库安装，要求见 [官方 IPA 安装说明](https://docs.playcover.io/getting_started/download_ipa.html)。本项目不提供游戏安装包。
3. **完全退出游戏**，右键 App 库中的“绝区零”→ **设置**，核对下表。选项名称参考 PlayCover **3.1.0（1633）**。

| 页面 | 设置 | 值 |
|---|---|---|
| 图像 | iOS 机型 | iPad Pro 12.9 英寸第 5 代（M1 / 8GB） |
| 图像 | 分辨率 | **Resizable（可缩放）**；部分中文界面显示 `settings.picker.adaptiveRes.6` |
| 图像 | 长宽比 | **自定义，填写 `1920:1080`** |
| 图像 | 分辨率缩放 | **`1.0`** |
| 图像 | 修复窗口化显示问题 | 开启，方式为“正常” |
| 图像 | 设备方向 | 默认 |
| 图像 | 隐藏标题栏 | 关闭 |
| 绕过 | PlayChain | 开启，其余开关关闭 |
| 杂项 / 详细信息 | PlayTools | 保持已安装；不要点击“移除 PlayTools” |

**先选 Resizable，再设置自定义长宽比**，不要混用分辨率菜单里的“自定义”或“1080p”。`1920:1080` 表示 16:9，窗口可自由缩放；保持游戏内容铺满宽度、底边对齐，没有左右或底部黑边。一条龙会自动排除标题栏并适配截图。

配置后启动游戏，由本人完成资源下载、协议和首次登录，确认能进入游戏并保留登录状态。无需制作或导入触屏键位图。

## 2. 安装并启动一条龙

需要 **Git、uv 和原生 arm64 Python 3.11**（`>=3.11.9,<3.12`）。缺少 Git 时先安装 Apple Command Line Tools；uv 安装见 [官方文档](https://docs.astral.sh/uv/getting-started/installation/)。

首次部署到新目录：

```shell
git clone --branch main https://github.com/Aurxs/ZenlessZoneZero-OneDragon-MacOS.git
cd ZenlessZoneZero-OneDragon-MacOS
uv sync --frozen --python 3.11
PYTHONPATH=src uv run --no-sync python -m zzz_od.macos.main
```

日常在仓库根目录执行最后一行即可，无需重复安装依赖或克隆测试仓。

### 更新已有安装

本 Mac 版从 `https://github.com/Aurxs/ZenlessZoneZero-OneDragon-MacOS.git` 的 `main` 分支获取已发布到该分支的代码。仓库已改名，已有本地安装目录无需改名，旧 `origin` 地址按下方异常处理更新即可。**旧版本 GUI 的代码源曾指向上游，首次获取代码源修复请使用下面的终端步骤。**

1. 退出一条龙 GUI、CLI 和联调进程，在原项目目录打开终端，检查来源、分支和本地改动：

   ```shell
   git remote get-url origin
   git branch --show-current
   git status --short
   ```

   应分别显示上述 Mac 仓库地址、`main`，以及空的状态输出。如果来源或分支不符，先确认当前目录是否为原 Mac 版安装目录；有本地源码改动时，先备份或自行提交，处理完成后再更新。来源已被旧 GUI 改写时，按下方异常处理恢复，不要直接强制覆盖。

2. 拉取更新：

   ```shell
   git pull --ff-only origin main
   ```

   提示 `Already up to date` 表示已与远程分支一致；若提示无法快进，说明本地历史与远程分叉，需先保留本地提交并处理，不能用强制重置代替正常更新。

3. 如果拉取结果包含 `pyproject.toml` 或 `uv.lock` 的变动，再同步依赖；普通代码更新跳过此步：

   ```shell
   uv sync --frozen --python 3.11
   ```

4. 重新打开原启动入口，或在项目目录执行：

   ```shell
   PYTHONPATH=src uv run --no-sync python -m zzz_od.macos.main
   ```

正常更新会保留账户、任务计划、运行记录、本机配置及已下载模型，无需重装 OJD。仓库位置、虚拟环境和 Python 未变时，普通代码更新无需重新授权或重建本机启动应用。

### GUI 更新入口

获取代码源修复后，打开 **资源管理 → 资源 → Mac 版代码同步**，点击 **设置** 可核对：

- **代码源**为“自动”或“Mac 版（Aurxs / GitHub）”，两者都只使用 Mac 仓库，不会回退到上游 CNB/Gitee 代码。
- **代码分支**为“Mac 主分支”（`main`）；旧配置中的普通 `test` 分支会回到 `main`，显式开启的自定义分支保留。
- **强制更新**会丢弃本地源码改动，Mac 新配置默认关闭；已有设置保留，有源码改动时应先自行保存。

停止运行中的任务后点击 **代码同步**，更新完成后重启。GUI 不会执行 `uv sync`；若本次更新修改了依赖，先退出程序，在终端同步依赖后再启动。Mac 不显示仅适用于 Windows 的启动器下载和 EXE 自动更新选项。

地区预设中的 CNB/Gitee 仍可用于模型等资源下载，代码始终来自 Mac 仓库。模型资源与项目代码来源不同，不代表更新到了 Windows 版。

### 更新错版本或没有 Git 元数据

旧 GUI 的代码同步不读取克隆时的 `origin` 作为唯一来源，而是按 `config/repository.yml` 的代码源拉取，并将 `origin` 恢复为配置中的主仓库。旧配置的主源和备用源均为上游，且强制更新默认开启，因此可能把 Mac 代码替换为上游版本。

如果 `origin` 仍是旧的 `Aurxs/ZenlessZoneZero-OneDragon.git` 地址，或只是被改写为上游、Mac 源码和本地历史仍在，退出一条龙后可先更新来源，再按上面的终端步骤更新：

```shell
git remote set-url origin https://github.com/Aurxs/ZenlessZoneZero-OneDragon-MacOS.git
```

如果 Mac 入口已经丢失，或恢复来源后 `git pull --ff-only` 仍无法快进，先保留并备份原目录，按首次部署步骤在另一个目录克隆并安装 Mac 版，不要强制重置或覆盖原目录。退出程序后迁移个人配置和所需模型，再核对新目录的路径及权限；不要用整份旧 `config/` 覆盖新目录，尤其不要复制旧 `config/repository.yml` 和 `config/project.yml`。

通过 GitHub「Download ZIP」获取的目录没有 Git 元数据，不能直接执行 `git pull`，同样按新目录克隆的方式迁移。旧 `.venv` 和本机开发 `.app` 含原目录路径，不要直接复制复用。

## 3. 配置一条龙

### 游戏设置

打开 **设置 → 游戏设置 → Mac 运行设置**，配置当前账户：

| 项目 | 配置 |
|---|---|
| 游戏平台 | **macOS PlayCover**，保存后重启一条龙 |
| 游戏应用标识 | 国服为 **`com.miHoYo.Nap`**；其他客户端按 PlayCover 详情页填写 |
| PlayCover 游戏路径 | 默认安装位置留空；其他位置填写实际完整 `.app` 路径 |
| 自动适配游戏窗口 | **开启**，无需手填标题栏高度或顶部裁剪值 |

其他运行参数保持默认即可。游戏路径不能填写别名或 `Info.plist`。

### 手柄服务

打开 **设置 → 手柄 → 手柄服务**：

1. 点击 **一键配置**，安装或复用 OJD 官方组件，并自动保存路径、开启自动启动。
2. 按系统提示完成管理员授权及输入权限；点击 **检查** 核对服务状态。
3. 点击 **连接手柄**，确认显示“已连接，可以开始准备游戏”。无需另开 OJD GUI 或创建第二个手柄。

动作按键和界面快捷键也在“设置 → 手柄”，应与游戏内手柄键位一致。

### 权限和资源

- 在 **系统设置 → 隐私与安全性** 中，为实际启动一条龙的终端、Python 或开发 `.app` 授予**屏幕录制**权限；启动时切换手柄模式还需**辅助功能 / 事件投递**权限。按实际弹窗授权后重启对应程序；OJD 的输入权限另按系统提示授予。
- 在一条龙 **资源管理 → 资源** 中准备 OCR 和任务所需模型：自动战斗需要闪光识别，迷失之地另需检测模型。等待下载和初始化完成后再运行任务。

## 4. 准备游戏并运行

1. 游戏和一条龙保持在**同一个 macOS 桌面 / Space**，使用窗口模式；运行时不要最小化游戏或锁屏。
2. 在 **一条龙 → 运行** 页点击 **准备游戏（启动并切换手柄）**。程序会按需启动游戏、短暂置前切换输入模式，直至确认手柄大世界；遇到密码、验证码、扫码或协议页面，先自行处理后重试。
3. 准备成功后，配置体力计划、编队和自动战斗策略。普通体力战斗无需先校准；首次运行迷失之地前，须完成下方的手柄镜头校准。
4. 运行实例设为 **仅运行当前**，“结束后”设为 **无**。按任务卡片的 Mac 适配提示选择任务，关闭“Mac 暂未适配”项，再点击开始。

运行期间只保留一个一条龙 GUI、CLI 或联调进程占用手柄和采集。“手柄已连接”后仍需执行“准备游戏”。

### 手柄镜头校准（迷失之地必做）

校准测量右摇杆推动时长与镜头转动距离的关系，供迷失之地自动寻路使用，不是虚拟手柄的连接或按键校准。

1. 完成上面的“准备游戏”，在游戏中进入迷失之地入口层，停在画面里只有一个感叹号交互图标的位置，保持手柄模式。
2. 在一条龙打开 **一条龙 → 灵敏度校准**，点击 **开始**。程序会短暂转动镜头，再反向恢复；期间不要操作游戏。
3. 日志出现 **“Mac 转向校准已保存”**、应用显示 **“Mac校准已完成”** 后，才算成功。参数保存在当前账户，切换账户后需要分别校准。

若提示“校准需要唯一感叹号”或测量不可信，调整入口处的镜头，使唯一图标清晰可见后重试；失败不会覆盖原参数。程序不会自动把角色传送到校准位置。详细原理见 [Mac 镜头转向校准](../zzz/application/macos_turn_calibration.md)。

普通体力战斗可直接使用原有策略；缺少有效镜头参数时，仅关闭本次战斗的周期自动转向，攻击和自动锁定照常执行，无需手动修改策略。已有有效校准时，自动转向沿用策略设置。

## 常见问题

| 现象 | 处理 |
|---|---|
| 窗口竖屏、裁切或有黑边 | 退出游戏，复核 Resizable、`1920:1080`、缩放 `1.0`、默认方向和显示标题栏，再重开 |
| 冷启动找不到游戏 | 核对游戏应用标识和 `.app` 路径；默认安装位置可留空 |
| 无法截图、启动点击无响应或切桌面后画面冻结 | 核对实际启动入口的屏幕录制、辅助功能权限，并将游戏放回同一桌面后重试 |
