# macOS 每日日常迁移计划

本文记录用户下一阶段日常流程与现有应用的对应关系，以及接入 Mac 的实施顺序。它是设计计划，不代表这些日常已经在 Mac 实机通过。当前证据与完成状态统一见 [迁移实施进度](macos_migration_progress.md)，启动前置见 [启动点击方案](macos_bootstrap.md)，已通过的单次模拟室范围见 [手柄实战模拟室](application/macos_combat_simulation.md)。

## 目标与前置

用户目标顺序为：每日登录 → 抽签 → 录像店经营 → 咖啡 → 清 320 电量 → 任务面板领取 60 菲林每日奖励 → 周奖励九宫格 → 右上角绿色通行证进度与奖励。

先完成自动启动前置和 GUI 接入，再开发完整日常。自动启动必须由一条龙检测输入模式、按需进入设置切手柄并截图确认，不能要求每次手动准备。日常期间优先使用原生手柄，CUA 仅用于开发观察，不进入运行依赖。固定边界沿用[迁移方案](macos_migration.md)：新增平台适配与上层导航，不修改既有 Windows Xbox/DS4、OJD 或 HID 底层实现。

用户已确认手柄迁移优先范围就是七项：每日签到、录像店、咖啡、体力计划、活跃度奖励、丽都周纪、通行证奖励。启动与 GUI 是共同前置；七项之外的玩法后置，不把完整默认组的其他应用一并开放。

本轮核对本地源码与知识文档，并接入原体力计划的 Mac 分支；未操作游戏、未修改运行配置，也未验证每日资源或奖励数值。

`daily_signin` 的含义是“每日签到玩法代理”，与登录游戏是两件事。[默认配置](../../../src/zzz_od/application/daily_signin/daily_signin_config.py)选择 `hou_hou_bakery`；现有 [GUI 选项](../../../src/zzz_od/gui/app_setting/daily_signin_setting_flyout.py)可改为 `scratch_card` 或 `trigrams_collection`。[卦象集录](../../game/screens/卦象集录.md)与[吼吼饼铺](../../game/screens/吼吼饼铺.md)文档记录三者共享同类每日领奖次数。因此初版只选择一个；“抽签”若实拍为阿朔占卜，应映射到 `trigrams_collection`，不能同时串跑三个签到应用。

绿色图标目前只有语义对应，没有本机画面证据。`city_fund` 最符合“通行证进度/奖励”，因为它处理成长任务和等级回馈；但现有 PC 文档入口在菜单底部，不足以证明用户所说的 iOS 右上角图标。另一个相关入口 `ridu_weekly` 已由九宫格描述对应。后续观察图标打开后的标题与标签：出现“成长任务/等级回馈”才确定为丽都城募，出现 BINGO/积分特赏则是丽都周纪；其他标题先建档，再决定是否需要新应用。不能只按颜色或位置点击。

## 运行顺序与配置

相关应用的仓库默认顺序由各应用常量的 `PRIORITY` 和[工厂排序](../../../src/one_dragon/base/operation/application/application_factory_manager.py)确定：每日签到 300 → 录像店 400 → 咖啡 500 → 体力刷本 600 → 活跃度奖励 700 → 丽都城募 800 → 丽都周纪 900。刮刮卡本身 `DEFAULT_GROUP=False`，由每日签到代理调用。默认组还包含邮件、兑换码和其他周常等应用，不能将“默认组存在”视为用户授权本轮全部运行。

Mac 日常只启用本计划范围，并将丽都周纪排在丽都城募之前，符合用户顺序。使用现有实例级 `one_dragon` 组配置保存启用状态与顺序，不改全局优先级。[应用组配置](../../../src/one_dragon/base/operation/application/application_group_config.py)保留用户已保存顺序，新增应用默认禁用；不能只改常量就假定当前实例顺序会改变。

运行顺序：

1. 自动启动前置确认缓存登录、手柄输入和大世界；处理已建档的登录后弹窗。
2. 每日签到代理运行一个已确认的签到玩法；当天已领则正常跳过。
3. 录像店完成经营，或确认正在营业后跳过。
4. 咖啡完成点单，或确认当天已喝；回大世界后重新读实际电量。
5. 体力计划按已配置副本消耗可用电量，记录目标与实际差额。
6. 活跃度奖励确认满档后领取；若前序失败导致活跃度不足，保留未完成结果。
7. 丽都周纪领取当前可领积分与奖励；不自动扩展到其他周常玩法。
8. 经实拍确定的通行证应用领取成长任务与等级奖励，最后返回大世界并释放输入。

[咖啡配置](../../../src/zzz_od/application/coffee/coffee_config.py)的 `run_charge_plan_afterwards` 保持关闭，由组内 `charge_plan` 统一运行，避免咖啡内部执行一次、应用组又执行一次。录像店可优先验证澄辉坪营业点，咖啡可优先验证汀曼咖啡：现有文档记录这两个落点可直接交互，能减少转向校准；这是待验证的 Mac 方案，不等于传送导航已支持。

| 参数或选择 | 初版计划 | 依据与限制 |
|---|---|---|
| 活动实例 | 仅当前 Mac 实例，单账号执行 | [一条龙入口](../../../src/zzz_od/application/one_dragon_app/zzz_one_dragon_app.py)需按单实例接入与清理，不能直接开放原多实例循环 |
| 签到商店 | `trigrams_collection`，阿朔占卜 | 用户已明确选择；仅当前 Mac 实例修改，不改变仓库默认，不同时运行其他同类签到 |

## 电量、奖励与日期边界

“320 电量”和“60 菲林”是用户目标，不是本计划新增的固定游戏常量。本轮核对的咖啡源码与数据没有可用于确认补充量的字段，活跃度应用也没有读取菲林奖励数量。不能据此证明每次咖啡补 60、每日固定可花 320，或现有领奖成功就等于实际得到 60 菲林。

现有 [ChargePlanRunRecord](../../../src/zzz_od/application/charge_plan/charge_plan_run_record.py)按每 360 秒恢复 1 电量、估算上限 240 处理；24 小时理论自然恢复 240 是据此计算，不是当前账户实测。[恢复电量文档](../../game/screens/恢复电量.md)另有储蓄电量和以太电池规则。首轮应保存咖啡前后、战斗前后的实际读数和单次消耗，以这些数据解释当天可消耗总量；版本活动、已喝咖啡、开跑时未满电与跨日都会改变结果。

当前 Mac 单次模拟室已支持一张或五张卡片，实际消耗分别为 20 或 100；完整 100+20 顺序计划已通过，证据见迁移进度。通用计划对模拟室按“卡片数 × 20”预估，默认数量仅预估 20，不能用这一预估替代实机 100 的核对。实现 320 的精确组合至少需要额外的卡片选择能力，例如 100×3+20；单卡及 100+20 已实机通过，320 整体仍需足够电量时验证。只完成三次 100 时应报告消耗 300、仍差 20，不能写“已清 320”。资源不足则报告实际完成值和剩余电量，不自动补资源。

每日奖励先验收“活跃度满档、可领取奖励已领取、结果页面确认”，再用实拍奖励明细验证 60 菲林目标。现有[快捷手册日常文档](../../game/screens/快捷手册-日常.md)记录 100/200/300/400 活跃度档，不提供 60 菲林数值证明；未满档、已领取和实际新领取应分别报告。

日期计算复用[账户区服偏移](../../../src/one_dragon/base/config/game_account_config.py)和[运行记录](../../../src/one_dragon/base/operation/application_run_record.py)的游戏日，不按 Mac 本地零点另建规则。国服当前偏移为 UTC+4，其日期边界对应北京时间 04:00；海外服使用各自配置，不写死北京时间。恢复或跨日后重新检查资源与日常状态。`ridu_weekly` 虽然是周玩法，其[运行记录](../../../src/zzz_od/application/ridu_weekly/ridu_weekly_run_record.py)未指定 `WEEKLY`，实际沿用每日检查，这允许每日领取新完成的积分，不能因应用名字就改为一周只运行一次。丽都城募也有每日、本周、本期任务，领奖时以当前页面为准。

## Mac 输入依赖与实施落点

### 先转换现有流程，再逐项实测

共同开发习惯统一维护在 [Mac 手柄迁移开发约定](macos_gamepad_workflow.md)，涉及日常路径的开发与调试先读该文件。每日签到继续使用用户指定的阿朔占卜（`trigrams_collection`），不改为刮刮卡或吼吼饼铺。

[Mac 控制器](../../../src/zzz_od/controller/zzz_macos_controller.py)已有手柄动作、移动、交互和截图。坐标点击仅在提供明确 `gamepad_key` 时才会转换成手柄组合；拖动、滚轮、文本输入明确拒绝。移动端切入手柄后触屏失效，不能把 PC 的 OCR 点击、Alt 解锁光标或鼠标拖动直接转发给启动点击器。

| 公共依赖 | 当前限制 | 迁移方式 |
|---|---|---|
| 传送到商店/NPC | [Transport](../../../src/zzz_od/operation/transport.py)和地图选择仍使用 PC 点击流程；已通过的手册导航只覆盖模拟室基础材料 | 新增已观察页面的手柄地图导航，复用地图数据；未解锁目标明确失败，不猜坐标或方向 |
| 返回大世界 | [BackToNormalWorld](../../../src/zzz_od/operation/back_to_normal_world.py)包含大量坐标点击与通用弹窗处理 | 对已适配页面新增有页面证据的 B/关闭路径；未知页面停止并保存截图，不能盲按返回 |
| 每日签到 | 刮卡要三段 `drag_to`；卦象也含拖动，饼铺仍需页面选择 | 先确认原生手柄的实际刮取/占卜操作；没有证据前不推断摇杆或 A 能代替拖动。确实无法覆盖时单独设计输入模式切换、必要点击/拖动与恢复，并明确前台需求 |
| 录像店 | 宣传员滚动、主题筛选与营业确认均有点击，主题列表可拖动 | 保留选人/主题业务，新增焦点识别与有限导航；优先验证推荐上架，保留配置指定宣传员 |
| 咖啡 | OCR 点击选项，跳过动画还有“先拖鼠标再点”的 PC 特例 | 保留候选咖啡与已喝状态，不搬用显鼠标特例；按实拍手柄提示实现点单与确认 |
| 活跃度、周纪、城募 | 现有应用依赖奖励档坐标、OCR 点击或纯坐标按钮 | 复用领奖范围与运行记录，新增对应页面焦点和结果判定；领取后用新帧确认，避免重复确认 |

首轮日常不需要桌面键盘输入文本。PC 的 F、W、Alt 只是原流程描述，Mac 应通过既有语义动作与手柄接口表达交互、移动、打开菜单和返回；启动凭据输入的处理边界归启动前置。

实现继续复用 ApplicationFactory、应用配置、Operation 和运行记录；Mac 的导航差异放在新增手柄 Operation，由平台选择接入业务应用。不要另写一套独立日常脚本取代现有 GUI、计划和暂停/停止机制。画面差异进入 `ios_gamepad` 资源配置，保持 PC 资源原样；当前[资源目录](../../../assets/game_data/platform/ios_gamepad/)只有手册、菜单、战斗与模拟室差异，日常商店与奖励页需按实拍补档。

## 原体力计划的首版接入

[ChargePlanApp](../../../src/zzz_od/application/charge_plan/charge_plan_app.py)在 Mac 执行前调用[计划检查](../../../src/zzz_od/operation/gamepad/charge_plan.py)核对整份原计划；其他平台继续走原节点。支持范围仍为调查专项、默认等级、默认五卡或显式五卡、当前编队。不支持的项返回具体序号与字段；开启恢复电量或双倍活动时明确拒绝，不静默忽略、不修改设置。

Mac 分支保留原计划顺序、`plan_times`、`run_times`、每日重置与循环扣减。每场复用手柄手册传送和单次挑战，先从已建档预设页读实际消耗 100，再决定出战；默认计划的 20 电量预估不用于放行。胜利计数由原配置保存，单场成功却没有新增胜利记录时停止。每场结束走已验证路径返回大世界，再处理下一项；不使用结果页“再来一次”。

所有首版支持计划都需要 100 电量，因此不足 100 时直接结束本次调度，经已建档预设与材料分类返回大世界；保留未完成次数并报告“电量不足”，不会伪称整份计划完成。未知返回页不发送按键。停止与暂停由公共运行上下文及单次操作释放输入；本分支没有新建 Application 或另一份任务配置。接入代码与离线检查通过不等于 GUI 或重复战斗实机验收，更不代表已支持精确清 320。

## 分阶段实现与验收

| 阶段 | 交付 | 本阶段完成标准 |
|---|---|---|
| D0：启动与 GUI | 自动启动前置、当前实例的原体力计划入口接入 | 从已缓存登录的启动状态开始，一条龙自动确认手柄、进入挑战并返回；GUI 暂停/恢复/停止都释放输入；不依赖 CUA 或人工切手柄，不增加独立单次任务 |

| D5：整组日常 | GUI 中可选择本计划顺序并查看结果 | 自动启动到最终返回大世界全程由一条龙执行；分项结果、实际耗电、奖励证据与未完成原因可查看；跨日按游戏日重置 |

## 下一阶段：更换体力材料与副本

原版“体力计划”支持配置多个材料或副本并按顺序运行。目前 Mac 只支持基础材料的调查专项，即当前角色升级材料；修改配置中的目标并不意味着其他副本已经能运行，运行前适配检查会明确拦截。后续复用原配置、次数记录与自动战斗，补齐其他材料分类、预设/敌人选择和对应页面的手柄导航，不另建 Mac 任务体系。2026-10-26 基础日常完成后，用户要求将此项提上日程：恶名狩猎 → 体力自定义材料 → 迷失之地周常。材料选择沿用原体力计划 GUI，先支持基础材料的其他专项，再扩展技能、晋升等分类，逐项开放适配范围。
