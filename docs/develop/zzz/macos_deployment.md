# Mac 部署教程（PlayCover 原生手柄）

适用于 Apple Silicon Mac，通过 **PlayCover 4.0 Preview** 运行 iOS 版《绝区零》，使用一条龙原 GUI 配置和执行任务。**PlayCover 3.x 不适用此教程。** 当前 Mac 使用源码环境，本文中的本地开发 `.app` 仍依赖仓库和 `.venv`。

按「游戏可正常登录 → PlayCover 设置 → 一条龙环境 → 平台与权限 → 手柄组件 → 准备游戏 → 任务」的顺序完成首次部署。已有可用环境可直接核对缺少的步骤，无需重装。

## 1. 准备游戏和工具

- Apple Silicon Mac，使用原生 arm64 终端和 Python。代码依赖 Python `>=3.11.9,<3.12`，下文由 uv 准备 Python 3.11。
- 安装 Git 和 [uv](https://docs.astral.sh/uv/getting-started/installation/)。已有 Homebrew 时可执行 `brew install uv`；`git --version`、`uv --version` 应能正常输出版本。
- 从 [PlayCover 4.0.0 Pre-release 官方发布页](https://github.com/PlayCover/PlayCover/releases/tag/4.0.0-prerelease) 获取 **4.0 Preview**（官方标签为 `4.0.0-prerelease`），按 [PlayCover 官方安装说明](https://docs.playcover.io/getting_started/download_playcover.html) 放入「应用程序」。不要使用默认稳定版入口中的 3.x。再导入自己合法取得、可用于 PlayCover 的游戏 IPA，方式见 [官方 IPA 说明](https://docs.playcover.io/getting_started/download_ipa.html)。
- 首次自行完成游戏资源下载、登录、必要协议和新手流程，确认能进入大世界。后续一条龙可使用已保存的登录状态，遇到密码、验证码等仍需本人处理。

版本要求以用户当前可用的 **4.0 Preview** 为准。官方发布说明列出了可缩放窗口及 macOS 26 手柄相关修复；本文菜单项按该预发布版本的源码核对。不能用其他安装包的内部版本字段推断 3.x 可用，最低系统版本也尚未完整验证。

## 2. 配置 PlayCover 中的游戏

**先完全退出游戏，再在 PlayCover 应用库中右键《绝区零》→「设置」。** 下列设置属于这一个游戏；PlayCover 菜单栏中的全局「设置」另有安装偏好。图像等设置需重新启动游戏才生效，见 [官方图像设置说明](https://docs.playcover.io/settings/graphics.html)。

下表为配置参考，数值来自已读取的 MacBook Pro 环境；**尚未逐项核对 Mac mini 当前 4.0 Preview 的实际设置**。必需的画面条件是 **16:9、内容铺满窗口宽度并贴底**；机型、缩放和兼容开关不要求每台 Mac 都相同。配置来源与核对范围见[迁移进度](macos_migration_progress.md)。

### 图像设置（Graphics）

| 选项 | 配置参考 | 说明 |
| --- | --- | --- |
| 选择 iOS 机型 | iPad Pro 12.9 英寸、第 5 代、M1（`iPad13,8`） | 用于复现现有布局；实际游戏画质还受游戏内设置影响 |
| 分辨率 | `Resizable`（可缩放窗口） | 可拖动调整窗口大小；部分构建可能仍显示英文 |
| 长宽比 | 自定义 `1920:1080`，即 **16:9** | 选择固定 16:9 也符合采集条件；不要选自由比例或随 Mac 显示器变成 16:10 |
| 分辨率缩放 | `2.0` | 首次部署可沿用，再按性能调整；它不等于一条龙的截图顶部裁剪 |
| 禁用显示器息屏 | 开启 | 防止游戏运行期间显示屏自动关闭；不保证锁屏或跨桌面后继续运行 |
| 隐藏标题栏（Hide titlebar） | 关闭 | 一条龙默认自动处理顶部标题栏，无需手填本机历史裁剪值 |
| 浮动窗口（Floating window） | 关闭 | 首次使用普通窗口布局 |
| 修复窗口化显示问题 | **开启**，方式为正常（Normal） | 开关与修复方式分别设置；参考环境未使用备用方式 |

若找不到 `Resizable`，先确认安装的是上方链接中的 **4.0 Preview**，并确认游戏已注入 PlayTools。这里不提供退回 3.x 的替代步骤。一条龙会把有效内容归一化到 1920×1080；物理窗口无需占满 1920×1080 像素。自动裁剪只处理顶部余量，左右或底部有黑边、比例变化时应先恢复布局，详见[采集缩放说明](application/macos_capture_scaling.md)。

### 键盘映射（Keymapping）

一条龙使用 OJD 提供的**原生虚拟手柄**和游戏内手柄界面，无需导入 PlayCover 触屏键位文件。PlayCover 键位映射用于把输入变成触摸，作用见[官方键盘映射说明](https://docs.playcover.io/settings/keymapping.html)。

| 选项 | 配置参考 | 说明 |
| --- | --- | --- |
| 启用键盘映射布局 | 参考环境开启，可保留已有设置 | 无需为自动任务新增触屏映射；自行添加过手柄触屏映射时，应排除与原生手柄重复响应 |
| 智能按键映射 | 开启 | 检测到文本输入时停用映射；不负责切换游戏内输入类型 |
| 启用滚轮 | 开启 | 自动任务不依赖这个选项 |
| 禁用原生鼠标输入（Disable Built-in Mouse Support） | 关闭 | 先按参考值配置；启动准备在触屏布局下可能需要短暂前台点击 |
| 鼠标灵敏度 | `50` | 属于 PlayCover 鼠标映射；Mac 右摇杆寻路另有[镜头校准](application/macos_turn_calibration.md) |

### 绕过（Bypasses）

| 选项 | 配置参考 | 说明 |
| --- | --- | --- |
| 启用 PlayChain | 开启 | 与游戏登录凭据存储有关；已有可登录配置应保留 |
| PlayChain 调试 | 关闭 | 日常任务无需打开 |
| 启用绕过越狱检测 | 关闭 | 参考环境未将此项作为自动化前提 |
| 插入内省库 | 关闭 | 参考环境未启用；不要仅为接入一条龙而添加 |
| 同步检查麦克风权限 | 关闭 | 参考环境未启用 |
| 防止频繁调用 `usleep`（Prevent usleep call spamming） | 关闭 | 用于限制系统调用，不是后台保活开关 |

### 杂项（Misc）和 PlayTools

| 选项 | 配置参考 | 说明 |
| --- | --- | --- |
| PlayTools | 确认已注入 | 若提示未安装，使用「注入 PlayTools」；已安装时按钮通常显示「移除 PlayTools」，此时保留即可 |
| 启用 Metal 性能面板 | 关闭 | 首次配置保持无性能浮层的画面 |
| 在 root 目录启动应用程序 | 开启 | 指游戏工作目录为 `/`，不表示用 root 用户启动一条龙 |
| 忽略 Unity 键盘初始化错误、限制运动传感器更新频率 | 参考环境均关闭 | 属于兼容选项，已有可用配置可保留 |
| Discord 活动 | 按个人偏好 | 不作为自动任务条件 |

PlayTools 的图像控制等功能见[官方杂项说明](https://docs.playcover.io/settings/miscellaneous.html)。PlayBook 部分通用页面仍标注旧版本；本教程的选项归属、Resizable 与自定义比例以 [4.0 Preview 设置源码](https://github.com/PlayCover/PlayCover/blob/4.0.0-prerelease/PlayCover/Views/AppSettingsView.swift) 为准，部分选项在中文界面仍显示英文。

保存后重新打开游戏检查：横屏 16:9、没有左右或底部黑边、能正常登录。游戏内使用中文界面，手柄按键与一条龙 Xbox 映射保持一致。原生手柄模式由后文「准备游戏」自动确认或切换，无需每次手动切换。

## 3. 创建一条龙源码环境

在 macOS 终端使用以下 zsh 命令。首次安装从包含 Mac 适配的个人仓库 `main` 获取代码：

```shell
git clone --branch main https://github.com/Aurxs/ZenlessZoneZero-OneDragon.git
cd ZenlessZoneZero-OneDragon
uv sync --locked --python 3.11
PYTHONPATH=src uv run --no-sync python -m zzz_od.macos.main
```

`uv sync` 只在首次创建环境、缺少依赖或依赖有更新时执行；日常启动使用最后一条命令。普通使用无需测试仓和开发依赖，也无需安装 Windows 虚拟手柄驱动。

如需固定的本地 `.app` 启动入口，先确认已安装 Xcode Command Line Tools（缺少时运行 `xcode-select --install` 并完成安装），退出命令行启动的 GUI 后执行：

```shell
uv run --no-sync python tools/macos/create_dev_app.py
open .debug/macos/OneDragonDev.app
```

后续可直接打开这个 `.app`。它绑定当前仓库和 Python 路径，移动仓库或更换虚拟环境后才需要重建；已有授权的可用入口继续复用。详见[本地开发应用说明](../../../tools/macos/README.md#生成本地-gui-开发应用)。

## 4. 设置当前账户的平台与权限

先在账户管理中选择要运行的账户，再进入 **「设置 → 游戏设置 → Mac 运行设置（当前账户）」**：

| 选项 | 首次配置 |
| --- | --- |
| 游戏平台 | **macOS PlayCover**，保存后重新启动一条龙 |
| 游戏应用标识 | 国服为 `com.miHoYo.Nap`；须与 PlayCover 游戏「详细信息」一致，其他客户端的流程尚未据此验收 |
| PlayCover 游戏路径 | 默认安装位置可留空；自定义位置填写完整游戏 `.app` 路径 |
| 启动窗口等待 | 先保留 `45` 秒；这是等窗口出现的时间 |
| 自动适配游戏窗口 | **开启** |
| 标题栏高度、截图顶部裁剪 | 自动模式下保留原值；不要照抄其他机器的 `28` 点或 `56` 像素 |
| 界面操作间隔 | 先保留 `500` 毫秒；只约束界面步骤，不改变战斗策略时序 |

macOS 权限在 **「系统设置 → 隐私与安全性」** 中按实际请求的程序身份授权：

- **屏幕录制 / 屏幕与系统音频录制**：允许运行一条龙的入口采集游戏窗口。使用本地 `.app` 时确认对应应用；从终端启动时按系统列出的终端或 Python 身份处理。
- **辅助功能**：允许启动准备在必要时点击游戏设置、切换输入类型。
- **输入监控、输入控制相关提示**：首次连接 OJD 时按系统弹窗确认，并在一条龙手柄页查看诊断状态。

授权后如系统提示退出并重新打开，应重启实际运行入口。给 PlayCover 的权限不能代替给一条龙或 OJD 的权限；改用另一种启动入口时需重新核对。

## 5. 安装和连接手柄组件

进入 **「设置 → 手柄 → 手柄服务」**：

1. 点击「安装 / 检查 OJD 官方组件」的 **「一键配置」**。程序使用固定的官方签名版本 `0.6.0-alpha.1`，下载并校验组件；已有合格安装会复用，遇到不同版本会明确报错。
2. 完成本机弹出的管理员或输入权限确认。成功后「手柄组件路径」自动填写，「自动启动手柄服务」开启，无需另外手动启动 OJD。
3. 点击「连接手柄」，再用「服务与权限诊断 → 检查」确认服务及权限。连接只建立中立状态，不会自动操作游戏；仅显示连接成功还不能证明游戏已识别手柄。

保持手柄按键和界面快捷键的默认 Xbox 映射；若改过游戏内按键，两边需对应。组件安装细节见[手柄服务说明](macos_gamepad_service.md)，当前 GUI 入口以本文为准。

## 6. 准备游戏并首次运行

1. 完成启动时提示的资源下载，在「资源管理」确认所需模型就绪。首次可使用默认 CPU；闪光与迷失之地模型的 Core ML 开关按需开启。
2. 游戏使用普通窗口并留在**当前桌面（Space）**。此时只运行一个一条龙 GUI；使用 CLI 或联调脚本前先退出 GUI。
3. 在 **「一条龙 → 准备游戏」** 点击开始。游戏未运行时会先连接手柄再启动；已运行时复用窗口。程序会使用已保存账号进入，并在触屏布局下按需短暂切到游戏前台、点击设置切为手柄。
4. 以「准备游戏」成功并确认**手柄大世界**为完成标志，不能只看游戏窗口已打开或 OJD 已连接。遇到登录凭据、未知弹窗等提示，处理后重试；原生手柄模式下触屏操作失效属于布局变化。
5. 在原任务设置、体力计划、预备编队和自动战斗配置中选好目标与策略。首次先运行一个已支持的任务，例如活跃度奖励，核对结果和返回主界面，再启动整组任务。
6. 一条龙运行账户设为 **「仅运行当前」**，「结束后」设为 **「无」**；关闭界面提示暂未适配的任务。各任务的材料、模式与资源条件以自身提示为准。

同桌面失焦运行已有实测记录；**跨 Space、最小化、锁屏和睡眠不能当作可用运行方式**。「禁用显示器息屏」不保证这些情况继续渲染。窗口采集限制见[后台画面说明](../one_dragon/macos_input_capture.md)，功能和验收范围见[迁移进度](macos_migration_progress.md)。

配置完成后可改用[命令行入口](application/macos_cli.md)。以下命令只预览当前任务，不连接手柄或操作游戏：

```shell
PYTHONPATH=src uv run --no-sync python -m zzz_od.macos.cli --dry-run
```

## 7. 常见问题

| 现象 | 优先检查 |
| --- | --- |
| 提示需要 Apple Silicon 或 arm64 Python | 终端与 Python 是否在 Rosetta 下运行；`uv run --no-sync python -c 'import platform; print(platform.machine())'` 应输出 `arm64` |
| 图像设置灰显、提示未安装 PlayTools | 完全退出游戏，在该游戏「杂项」中确认 PlayTools 已注入 |
| 比例不符、截图错位、识别不到主界面 | PlayCover 是否固定 16:9、内容是否贴底且无左右黑边；一条龙自动适配是否开启 |
| 游戏能开但无法采集窗口 | 应用标识是否正确、运行入口是否有屏幕录制权限、游戏是否留在当前桌面 |
| 手柄已连接，游戏仍为触屏界面 | 先运行「准备游戏」并查看具体错误；核对 OJD 权限和启动入口辅助功能权限 |
| 切手柄时点击没有响应 | 检查辅助功能授权、游戏是否被其他窗口或弹窗挡住，以及是否修改过鼠标相关兼容设置 |
| 切桌面、锁屏或最小化后停止 | 恢复当前桌面的游戏窗口和有效画面，再按任务提示恢复；不要用兼容开关代替画面检查 |
| 某任务无法开始、整组被拦截 | 查看任务自己的 Mac 适配提示、当前账户、结束后操作及计划范围 |

常规 GUI / CLI 日志位于 `.log/log.txt`；本地开发 `.app` 另有 `.debug/macos/dev-app.log`。排查时记录 PlayCover 完整版本、设置项和具体失败日志，保留现有账户、计划与运行记录。
