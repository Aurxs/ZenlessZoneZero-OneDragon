# Mac 冷启动与已保存账号登录

状态：游戏未运行时的完整 GUI 冷启动与默认账号登录已实测通过，两种登录布局的实拍回放通过。已登录会话的输入模式准备也已通过 GUI 热切换验证，见[启动准备](macos_bootstrap.md)和[迁移进度](macos_migration_progress.md)。本流程不修改 Windows 登录、OJD 或 HID 底层实现。

## 职责与顺序

进程启动层负责在游戏未运行时先连接并保持虚拟手柄，再启动配置的游戏、选择唯一窗口和建立采集。游戏已运行时复用当前会话，不为准备输入模式而关闭重启。采集必须产生有效画面后，才能进入启动 Operation。

启动层由 `MacGameLauncher` 实现，按准确的 bundle ID 和窗口规则复用现有进程；没有运行进程时才校验并打开一次 `.app`。窗口等待默认45秒，由 `launch_timeout_seconds` 配置；`app_path` 留空时查找 PlayCover 的对应应用。初始化期间尚未实现取消等待，失败会释放输入和采集，不会关闭已经启动的游戏。

输入模式与登录画面由 `MacBootstrapGameSession` 负责。进程启动层通过 `controller.started_game_this_run` 提供「本次确实新启动游戏」的标记，用于允许启动过渡阶段被动等待；不把「进程存在」当作登录成功。该标记每次初始化清除，仅本次确实启动并取得对应窗口时为真。

默认账号指游戏当前已保存登录状态的账号；本流程不输入凭据，也不自动切换账号或区服。

准备流程保留固定优先顺序：已有手柄界面优先用手柄，手柄大世界直接成功；只有触屏画面的正面特征命中时才使用临时前台点击。成功条件始终是截图确认手柄大世界。

## 登录画面流转

| 当前画面 | 必要证据 | 动作与后续 |
|---|---|---|
| 品牌、警告、标题或配置加载 | 本次新启动，或识别到对应加载特征 | 只被动等待，进入已建档登录页后再判断 |
| 已保存账号的手柄登录就绪页 | 登录主提示与手柄提示同时命中，且没有凭据对话框 | A 进入一次，再等待服务器连接和加载 |
| 已保存账号的触屏登录就绪页 | 登录主提示与触屏布局特征同时命中 | 点右侧设置；复用已验证的输入页切换手柄，再用 B 返回登录页 |
| 切换后的手柄登录页 | 本次已确认手柄布局，且登录主提示命中 | A 进入一次，不再点击屏幕 |
| 服务器连接或场景加载 | 已发送进入动作，或命中已知加载特征 | 只等待新画面，不重复 A、不点击空白 |
| 登录后未完成挑战提示 | “当前正在处理”、取消与确认、选择文字和绿色 A 图标同时出现 | 与原登录流程一致取消旧挑战；先核对黄色焦点，必要时左移，再在取消高亮时确认一次 |
| 凭据、验证码、扫码或协议页面 | 对应提示明确出现 | 停止并提示完成所需登录操作后重试，不输入、发送验证码或同意协议 |
| 登录奖励或其它覆盖页 | 当前没有本轮可用实拍 | 本轮不自动关闭，停止或有限等待至超时 |
| 手柄大世界 | 大世界模板与手柄提示同时命中 | 完成准备 |

「点击登录」「进入游戏」和「点击进入游戏」不能互相替代，登录就绪按钮和凭据对话框可能使用相似文字。凭据页面判定必须先于进入动作，不用 OJD 连接状态代替游戏界面模式。

## 画面与区域

区域继续保存在 `ios_gamepad` 的 `Mac启动` 资源中，坐标与模板都以本轮原始截图为准，通过画面工具维护。现有世界、菜单、设置区域不改名。

| 区域 | 用途 |
|---|---|
| 登录-手柄主提示、登录-手柄进入提示 | 底部「进入游戏」文字加 A 圆形模板，双证据确认手柄登录就绪 |
| 登录-触屏主提示、登录-触屏设置 | 中部「点击进入游戏」加右侧竖排设置图标，双证据确认触屏登录就绪 |
| 登录-返回提示 | 登录设置底部右侧 B 提示，与已登录设置的提示位置分别识别 |
| 登录-凭据提示 | 中央固定区域内用成对提示检测需要用户完成的登录步骤 |

登录奖励若本轮出现，再补该具体页面的标题、手柄提示和出口；不预设可用 B 关闭所有弹窗。手柄登录页、触屏登录页及设置返回登录页均需单独归档；已登录世界的截图不能代替这些证据。

登录设置与已登录设置的输入页共用覆盖完整文字框的 OCR 范围，当前值和展开的选项保持分离。点击使用当帧文字框中心，不使用两套布局的共同区域中心。凭据检测只接受完整提示的组合，例如「输入手机号注册/登录」与「验证码」同时出现；不会因电视字幕等内容的单个「验证码」或「密码」词停止。凭据页面没有本轮实拍，只有文字守卫的离线验证。

## 等待和失败边界

- 本次新启动的过渡阶段允许最多60秒被动等待，首次明确动作后结束该等待许可。A 进入后的服务器与场景加载另允许最多60秒被动等待，不重复 A。
- 热会话中的未知画面保留现有八帧观察后失败。冷启动只扩大被动等待时间，不放宽点击证据，也不重复有副作用的动作。
- 每个进入、打开设置或切换布局的动作仍最多一次，并要求动作开始后的真实新像素帧。采集失效、窗口身份改变或连接断开时停止，不能继续发送登录输入。
- 热切换保留35秒总期限；已有登录页的会话进入后总期限为95秒。新启动会话的总期限为155秒，包含60秒启动过渡、35秒输入准备及60秒登录加载；启动层等待窗口的45秒另计。节点不另设35秒的提前截止。

## 最小验证

本轮12项 bootstrap 聚焦测试已通过，包含既有热切换行为、冷启动有限等待、两种真实登录布局、凭据组合守卫和登录加载上限。真实回放分别验证手柄登录页 A 一次后到达手柄大世界且零鼠标，以及触屏登录页四次点击、B 返回登录页后 A 进入；当帧模板、区域和 OCR 均来自归档素材。缺少实拍的凭据和奖励页面不伪造 fixture。

完整实机验收已通过 GUI 的「准备游戏」触发：游戏未运行 → 自动启动 → 触屏登录页四次必要前台点击切手柄 → B 返回登录页 → A 使用默认账号进入 → 截图确认 HIA 手柄大世界。运行期间没有 CUA 游戏动作，精确日志见迁移进度。

鼠标仍位于注入点附近时才恢复原位置，游戏仍为前台时才恢复原应用，避免覆盖用户主动操作。已是手柄登录页时零鼠标的分支已有实拍回放验证；本次完整冷启动走触屏切换路径。凭据、登录奖励、跨 Space 和初始化取消等边界保持各自的未验证或未实现状态。


“全新放送”是版本初的限时登录签到活动，不是每天必有的固定任务，不加入一条龙任务列表。2026-10-26 实拍登录后恰好出现该活动页：标题及“累计登录7天”说明、底栏手柄 B 返回同时出现时，准备流程核对可领卡片的黄色焦点后 A 领取；只确认本次领取产生的获得弹窗，再 A 确认，回到活动页后 B 返回。三个动作逐帧判断，不盲发连续 AAB，也不处理其他未知活动页。该页面不代表登录失败。
