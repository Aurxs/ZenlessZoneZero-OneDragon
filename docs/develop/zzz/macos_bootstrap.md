# Mac 启动阶段的输入模式准备

启动时需要识别当前输入模式，必要时在触屏输入仍可用时打开设置、切换手柄，再通过新截图确认。`game_session_entry` 集中选择平台入口，Mac 使用独立准备 Operation，Windows 沿用原登录操作。准备流程使用启动层已经连接的采集和手柄服务，不修改 Windows、OJD、HID 输入，也不改变 `ZMacController.click()` 的手柄约定。整体流程见 [macOS 迁移方案](macos_migration.md)，游戏未打开时的启动与登录见[冷启动说明](macos_cold_start.md)。

## 操作流程与调用位置

Mac 顶层应用在原任务列表执行前通过 `MacGameSessionPreparation` 显式执行 `create_game_session_entry(ctx)` 返回的操作。框架的窗口检查在窗口已经就绪时会直接通过，因此不能仅给应用设置默认登录操作而不调用它。准备服务以控制器及本次初始化次数 `run_generation` 为依据，同一次运行成功后复用结果；重新初始化、切实例或窗口失效后必须重新确认。后续子操作继续使用窗口检查，不在挑战过程中再次打开设置。

准备流程先获取当前窗口的新截图，再按画面证据选择路径：已经是手柄大世界时直接确认；触屏大世界从菜单进入设置，在输入页选择手柄；切换后只使用手柄返回，直到截图同时符合大世界及手柄提示才成功。每次点击后必须等待采集时间晚于该动作开始的新截图，点击投递成功不能代替画面确认。以动作开始为界，是因为 UI 可能在松开鼠标和恢复前台之前已更新，之后 ScreenCaptureKit 只报告静态画面的 Idle 状态，不生成新像素帧。

输入选择的优先顺序固定为：先识别已有手柄界面，能用手柄返回或进入时只发手柄键；只有触屏画面的正面特征命中后，才创建临时前台指针执行切换。已经是手柄大世界时直接成功，不能为了再次确认而打开设置或切回触屏。

画面区域由 `ios_gamepad` 平台资源提供，不修改公共 Windows 画面。每个有副作用的步骤只执行有限次数；未知画面、缺少手柄选项、画面未变化或窗口身份变化均明确失败，不盲点空白、不输入帐号密码、不修改 PlayCover 设置。登录页的模式、右侧设置和已保存账号进入各有独立实拍证据；凭据页面和未建档覆盖页不会由普通进入按键代替处理。

GUI 热切换与游戏未运行时的完整冷启动均已实测通过，冷启动使用游戏已保存登录状态的默认账号，最终截图确认 HIA 手柄大世界；具体日志、四次前台点击及 B、A 路径见[迁移进度](macos_migration_progress.md)。鼠标和原前台应用仍按指针层条件恢复。登录奖励页面未覆盖，凭据守卫只有离线验证。

## 目标和边界

`MacBootstrapPointer` 构造时绑定已经选定的 bundle ID、PID 和窗口 ID。构造和坐标预检不发送事件。默认保留 `CGEventPostToPid` 定向投递，但本机 PlayCover 对它没有响应，即使返回投递完成也不能视为有效点击。

启动 Operation 在确认触屏路径后显式选择 `foreground=True`：临时激活目标游戏进程，将鼠标移到核对后的目标点，再通过公开的 HID 事件接口发送一组左键按下、松开。点击结束后按指针层的条件恢复原鼠标位置和前台应用，避免覆盖用户在期间主动改变的状态。这段准备会短暂使用前台及鼠标；不能宣称整个启动过程都在后台。已经是手柄大世界时不创建该指针，也不移动鼠标。切换成手柄后仅发送手柄返回键。

投递前重新枚举 ScreenCaptureKit 窗口，核对三项身份，再读取 `CGWindowListCopyWindowInfo` 的当前全局边界。两种来源的窗口尺寸须一致，窗口须仍在屏幕上且为普通窗口。以 `SCContentFilter.pointPixelScale` 获取实际像素与逻辑点的比例，不假定 Retina 一定为 2 倍。没有图形会话、屏幕录制权限、辅助功能权限，或窗口关闭、重建、缩放信息不一致时明确失败。

## 坐标换算

上层只传游戏内容内的标准 1920×1080 坐标。默认自动模式与截图共用`infer_game_top_inset()`，按每次读取的窗口宽度和底边推算顶部，不复用初始尺寸。关闭自动模式后优先使用`top_inset_points`，否则将`top_inset_pixels`转换成逻辑点；剩余完整内容区必须是16:9。公式为：

- 自动顶部偏移逻辑点 = `窗口逻辑高度 - 窗口逻辑宽度 × 9 / 16`；手动模式使用已配置逻辑点或`top_inset_pixels / pointPixelScale`。
- 屏幕 X = 窗口左边界 + `游戏 X / 1920 × 窗口逻辑宽度`。
- 屏幕 Y = 窗口上边界 + 顶部偏移逻辑点 + `游戏 Y / 1080 × 剩余逻辑高度`。

坐标必须有限且满足 `0 ≤ X < 1920`、`0 ≤ Y < 1080`。自动模式要求铺满宽度、底边对齐，顶部余量须在0至64逻辑点内并允许一个单位的取整误差；不识别左右或底部黑边。异常尺寸、比例或身份不一致时停止。`resolve_point()`可只读检查当前换算结果。窗口移动和缩放后不复用旧边界，点击前重新读取。详见[采集缩放](application/macos_capture_scaling.md)。

## 结果与验证

`click()` 返回 `True` 仅表示按下和松开的投递调用均已完成。Apple API 返回 `void`，无法从返回值判断游戏是否接收；上层必须用新的截图确认切换手柄并返回大世界。失败抛出明确异常，不能继续进入自动任务。

最小测试使用假窗口与假 Quartz，覆盖 Retina 和标题栏换算、窗口身份和坐标范围拒绝、默认 PID 定向投递，以及显式前台路径的输入和恢复边界。Operation 测试覆盖已是手柄时零鼠标输入、触屏逐帧切换、投递后画面未变化、断线和未知画面失败。实拍与 OCR 快照归档到测试仓 `screens/Mac启动/`；实际整段准备的通过情况记录在迁移进度中，不把单次点击响应写成完整流程通过。

API 已对照本机 Xcode macOS SDK 的 `CGEvent.h`、`CGEventTypes.h`、`SCStream.h` 和 `AXUIElement.h`：`CGEventPostToPid` 从 macOS 10.11 公开，窗口字段 91/92 从 10.7 公开，`pointPixelScale` 从 14.0 公开。官方入口：[CGEventPostToPid](https://developer.apple.com/documentation/coregraphics/cgevent/posttopid(_:)?language=objc)、[pointPixelScale](https://developer.apple.com/documentation/screencapturekit/sccontentfilter/pointpixelscale)。


## 手柄大世界提示补充

大世界快捷手册模板命中后，LT 提示支持文字或独立图标模板确认。小窗口归一化可能使短文字 OCR 漏检，图标只在固定提示区匹配，不放宽大世界条件，也不以 OCR 缺失推断触屏。正式启动仍通过原准备入口；实拍见大世界画面文档。
