# 咖啡应用

咖啡应用复用原 `CoffeeApp`、`CoffeeConfig` 和运行记录。咖啡页面与入口差异见[咖啡店画面](../../../game/screens/咖啡店.md)。候选顺序为尚未喝过的额外咖啡优先、汀曼特调兜底；传送点和喝完后是否运行体力计划均读取原配置。

## Mac 手柄输入

Mac 仍使用原节点链。澄辉坪汀曼咖啡和布亚斯特城区片刻闲通过公共 `GamepadTransport` 传送，落点直接交互；六分街入口仍缺少手柄转向移动依据，在传送前说明不支持，不自动改为其他传送点。

已处于汀曼对话时直接恢复，不重传送。对话点单先按原候选顺序识别可见咖啡，再把“请来一杯汀曼特调！”这样的完整选项交给 `GamepadChooseDialogOption`，确认当前焦点后选择。没有候选时需要已经建档的继续对话动作。对话标题消失后还要确认大世界，不能把加载空白当成已喝过。

点单确认、已喝提示及电量确认使用 `operation/gamepad/shop.py`：只有已登记的按键与当前帧 `手柄-<动作名>` 专属提示同时具备时才发送输入。额外咖啡确认后回到对话点单节点，继续尝试其余候选；正式咖啡确认后按原配置决定是否运行体力计划。未记录所选咖啡时不能确认电量。

手柄不使用 PC 的显鼠标拖动；没有动画跳过键证据时有限等待动画完成。未核实的列表焦点、确认或返回动作先留图停止，保留配置与未完成状态；公共实测状态见[迁移实施进度](../macos_migration_progress.md)。

每日咖啡只有一次正常点单机会，消费后页面会改变。组件验收必须从未喝界面直接运行代码，不能先手动点单再只验证已喝分支。代码在对话点单和确认动作前保存关键帧，写盘失败不发送确认；动作后重新截图保存结果。同一消费节点记录已经发送的动作，异常重试不再次点单。未知状态先留图后停止，证据位于主仓 `.debug/images/Mac_咖啡店_*`，由日志输出实际路径。


## 2026-10-25 实机结果

澄辉坪汀曼特调已由原应用点单，实际奖励弹窗显示 80 电量，A 确认后自动回大世界。后续再次交互出现“还请明天再来吧”，程序识别该句后 A 返回，已喝分支通过。初次领奖因缺少电量弹窗映射分段恢复；`resume_from_charge_reward` 仅供已明确来源的中断恢复，默认关闭，不自动确认启动时已有的通用奖励。正式流程要求本次已经记录咖啡，且获得、电量与黄色确认同时命中。额外咖啡和另外两个入口尚未实机验证。
