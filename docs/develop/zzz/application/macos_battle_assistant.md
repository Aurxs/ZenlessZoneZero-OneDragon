# Mac 独立自动战斗与闪避助手

原 GUI「游戏助手 → 战斗助手」保留自动战斗、闪避助手两个模式，使用当前账户原策略、截图间隔、终结技和合并配置开关。Mac 已开放这两个固定入口；一条龙日常组不增加新的任务。

## 使用

从大世界启动会复用准备游戏流程确认手柄模式，然后等待进入战斗。已经在原生手柄战斗或战况菜单时可直接启动；菜单中等待，战斗 HUD 恢复后才放行策略。

暂停会停止策略并释放按钮、方向键、双摇杆和扳机；继续时按战斗 HUD 重新建立输入范围，保留终结技设置。停止、加载失败和异常收尾均执行释放。当前战斗的选择和结算沿游戏及各原任务完成，助手的启停结果不用于增加恶名或体力计划次数。

Mac 页面隐藏原 Windows 专享后台开关，旧 YAML 值保留；运行使用既有原生手柄，不检查 vgamepad / ViGEmBus，不调用 Windows 前台激活。Core ML 仍用原闪光开关，下次启动助手生效；关闭时使用 CPU。

## 接入

`AutoBattleApp` / `DodgeAssistantApp` 保留原模型、策略、事件和应用生命周期，只委托 `operation/gamepad/battle_assistant.py` 管理 Mac 入口和输入范围。启动时以普攻与固定 A 提示确认原生战斗；战况菜单以固定底栏及 A/B 提示确认。暂停回调与识别循环共用会话锁，并检查运行状态，避免重复建立范围。恢复复用既有战斗 HUD 保护，菜单和未知画面不继续发布战斗状态。

闪避助手补齐与原自动战斗相同的 finally 收尾，即使策略停止异常，也继续执行原应用的结束处理。没有更改 Windows Xbox/DS4、OJD 或 HID 输入实现。

## 实际验证（2026-10-28）

- 原 GUI 两种模式均完成开始、暂停、继续、停止，状态依次为运行中、暂停中、运行中、空闲；加载原「全配队通用」和「闪避」策略，Core ML 选项保留。GUI 在大世界等待，没有自动攻击或导航输入。
- 无报酬库萨里库实战中，原闪避助手运行并完成启停；自动战斗的最终串行验证明确记录 `actual_started: true`、`actual_resumed: true`，恢复后有右摇杆输出，暂停和停止时所有输入为中立。请求停止结束无限循环，原应用返回“人工结束”符合这项验证的停止方式。
- 早期发现会话暂停/恢复与识别并发的竞态，已在业务会话层修复；最终实战未再出现重复建立输入范围。原通用策略有暂停瞬间迟到调用被底层保护拒绝的记录，不把它当作仍在输出，也未为消除日志改底层输入。
- 练习明确免费奖励 0/3、深度追猎 OFF、无报酬模式；进入前的耗电模式被拒绝。用原生产操作临时关闭深度开关，清理后仅还原原 ON 状态，不按耗电下一步。游戏、原计划、队伍和实际计数不为测试修改；保护的六个文件哈希一致。
- 原无报酬提示在 A 确认后的动画帧会暂时漏字，现被动等待编队。恶名结果窄行 OCR 漏读时，以全帧 OCR 限定原目标区域，真实 0/1 能退出，不能用结果标题证明胜利。
- 15 项新增聚焦检查及 1 项直接受影响的结果解析检查分段通过，覆盖入口、配置保留、等待、阻断、暂停恢复、异常释放、无报酬与耗电确认区分；相关 Ruff 和差异检查通过。未全量测试，未重做已通过的离线模型对比。本次不据助手运行推断所有 Boss 都能通关或所有闪光样本准确。

正式代表图和全量 OCR 在测试仓 `screens/战斗画面/ios_assistant_*`，无报酬提示在 `screens/恶名狩猎/ios_unrewarded_notice.webp`。本机实机证据包括 `.debug/macos/auto_active_and_resumed_verified.json`、`auto_battle_verified_lifecycle.json`、`dodge_real_battle_result.json`、`assistant_lifecycle.jsonl`、`assistant_confirmed_validation.log` 和原 `dev-app.log`。本地计时桥只请求原上下文启停，场景操作由生产 Operation 执行；桥不是产品运行依赖。
