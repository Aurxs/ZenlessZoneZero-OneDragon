# Mac 标题栏裁剪与采集缩放

窗口采集继续使用原`MacWindowCapture`和1920×1080归一化，默认按固定16:9、铺满窗口宽度和底边对齐推算游戏顶部。共同约定见[手柄迁移开发约定](../macos_gamepad_workflow.md)。

## 默认自动适配

游戏设置的Mac运行设置新增“自动适配游戏窗口”，对应当前账户`capture_auto_top_inset`，缺少该字段的新旧账户均默认开启，不改写旧手动值。每个实际帧先去除SCK缓冲填充和窗口阴影，再计算`顶部裁剪像素 = 当前图片高度 - 当前图片宽度 × 9 / 16`，四舍五入后裁去顶部并归一化；不固定窗口大小或首次绑定时的高度。窗口放大、缩小及无标题栏时均重新计算。

截图与启动点击共用`infer_game_top_inset()`：截图以该帧`pixel_scale`换算限制，启动点击以当前窗口逻辑点计算。顶部余量只允许0至64逻辑点，容忍一个输出像素的取整误差；高度不足、余量过大或缩放元数据无效时拒绝使用，不自动回退到旧高度。仍保留原比例检查和帧龄保护，但裁后比例正确本身不能证明内容区正确。

前提是游戏内容铺满宽度且贴底；本规则不识别左右/底部黑边、其他内容比例或额外面板。遇到这类布局需要恢复约定的PlayCover窗口布局，或关闭自动模式后使用已确认的手动高度。设置页在自动模式下禁用两项手动输入，保留原值。

## 当前账户参数

关闭自动适配后，“标题栏高度（逻辑点）”非0时按每帧的窗口点到输出像素缩放计算顶部裁剪；为0时使用已有“截图顶部裁剪（旧像素配置）”。旧账户不自动改单位。修改裁剪方式或手动参数仍停止旧连接并要求重启，继续通过原账户配置与YAML适配器保存。

本机原手动值`capture_top_inset_points=28`及`capture_top_inset_pixels=56`保留，默认自动模式不使用它们。关闭自动模式后逻辑点优先；不能把其他机器的标题栏直接填成28，需先确认窗口装饰高度。

## 帧与启动点击

SCK输出可能为1倍或2倍。每个Complete帧保留自己的`pixel_scale`，由`scaleFactor`与`contentScale`计算；标题栏逻辑点据此转换成当前帧的裁剪像素。缓冲提取的`contentRect`已经包含内容缩放，保持原来的只乘显示缩放方式。字段定义见[Apple SCStreamFrameInfo](https://developer.apple.com/documentation/screencapturekit/scstreamframeinfo)。

启动专用指针在自动模式下每次重新读取窗口宽高和底边，使用相同推算规则；手动模式直接使用确认过的逻辑点高度，旧像素调用保持原换算。Windows输入和窗口路径未修改。

裁剪后仍须通过16:9校验；有效帧时间、Idle观察与过期保护保持原有语义，不能通过修改时间或拉伸图片来掩盖错误比例。

## 验证边界

自动模式以合成帧验证同一连接连续缩放、0.5/1/2倍输出、非整除宽度、无标题栏、异常高度和配置冲突；覆盖启动点击重新读取尺寸、控制器/准备Operation传递同一模式、GUI默认值和账户切换、手动值保留与关闭自动模式后的兼容路径。未启动游戏或手柄，本轮没有实机拖动窗口验收。

此前手动模式的原生只读实测为1072×631、scaleFactor=1、contentScale=1，裁去28后成功得到1920×1080；该历史证据不作为自动模式实机验收。
