# macOS 手柄实战模拟室

首版复用体力计划与实战模拟室原有业务，只替换手柄画面的导航。运行时通过控制器截图、OCR 与手柄输入完成，不依赖 CUA。输入模式切换由游戏会话入口负责；本段从已确认的手柄大世界或快捷手册开始。

## 快捷手册传送

`GamepadTransportByCompendium` 只支持「训练 → 实战模拟室 → 基础材料」。其他目标明确返回未支持，不把其他材料类型当作基础材料处理。原有计划计算、体力判断、队伍选择和战斗节点不在本段重写。

| 当前画面证据 | 动作 | 下一帧必须确认的证据 |
|---|---|---|
| 大世界快捷手册图标命中 | 快捷手册组合键 LT+A | 顶部标签文字及其中一个黄色填充标签 |
| 顶部当前标签的文字和黄色填充 | 按固定标签顺序发一次 LB 或 RB | 训练标签黄色填充 |
| 左侧当前分类文字和蓝色填充 | 按已确认分类顺序发一次方向上/下 | 实战模拟室蓝色填充，右列表显示基础材料 |
| 实战模拟室分类及基础材料文字，右列表尚无整行焦点 | A | 黄色或黄绿色大矩形边框包住基础材料文字 |
| 基础材料整行焦点 | A | 「是否立即传送？」弹窗 |
| 传送弹窗文字及确认按钮黄绿色填充 | A | 实战模拟室入口同时识别「挑战等级」与「下一步」 |

按键后由 Operation 的下一轮重新截图。每个节点都有有限重试和超时；进入右列表、请求弹窗、确认传送分别只发送一次 A。没有焦点证据、OCR 缺失或出现未知分类时不猜方向，也不连续按确认。顶部及左侧导航按固定、已验证的项目顺序决定方向，不根据 OCR 文字的左右关系推测焦点。

识别区域由 `ios_gamepad` 画面差异提供，运行时从 `screen_loader` 获取：快捷手册的「手柄-顶部标签」「手柄-分类列表」「手柄-副本列表」，菜单的「手柄-确认弹窗」「手柄-确认按钮」，实战模拟室的「手柄-挑战等级」「手柄-下一步」。顶部和分类使用目标文字附近的填充颜色；右列表要求完整大矩形轮廓包含目标文字，避免把按钮高亮或 NEW 标记误当作副本焦点。传送后只等待截图，不发送额外按键；加载空白或单独一个入口文字均不算到达。

画面事实见[快捷手册](../../../game/screens/快捷手册.md)。代表帧归档在测试仓 `screens/快捷手册/ios_*.webp`，通过项目的 Mac UID 遮挡方法处理副本，原始 PNG 保留。OCR 快照去掉 UID，只用于回放文字框，填充颜色与边框仍从实拍图计算。最小测试覆盖各步确认、一次性按键、缺少确认焦点不发送输入，以及入口两处文字必须同时命中。

## 单次挑战

`GamepadCombatSimulation` 接受原有 `ChargePlanItem`，使用原有 `auto_battle_context` 加载策略、识别战斗、执行战斗与停止动作。支持基础、晋升、音擎改装、技能四类普通材料、默认等级、一至五张卡片、当前编队或前六个预备编队；默认数量保留游戏中已保存的一至五张卡片，并绑定本场实际消耗；显式数量才进入编辑。不自动补电量，按配置选择编队，不替代原体力计划调度。每次调用只打一场。

准备阶段先加载计划指定的自动战斗策略，再用 `GamepadConfigureCards` 落实一至五张卡片，配置操作只到预设页、不按 Start、不消耗电量。预设页要求「挑战等级」「下一步」、目标专项完整黄色边框与实际电量同时可识别；配置后的实际消耗必须与目标卡数乘以20一致，再判断当前电量是否足够。按一次 Start 后等待「预备编队」「出战」同时出现；出战页再次核对同一目标耗电，再按一次 Start。两个动作分别有一次性记录，重试仅重新截图。未知编辑页保存截图后停止，不猜卡片增减操作。

进入战斗后要求现有普通攻击按钮识别通过，先启用 `MacBattleHudGuard` 输入保护，再启动既有自动战斗。控制器在最新帧无法确认战斗 HUD 时立即阻断战斗输入；Operation 停止策略并保留保护范围，避免结算页残余 X 误触「再来一次」。终结技过场暂时隐藏 HUD 时，只有新帧重新明确识别战斗或连携才能恢复。输入监测先用快速模板阻断，Operation 再直接检查结果候选帧的「挑战结果」与「完成」文字，不依赖原策略的结束检查间隔；正常战斗期间不额外执行每帧双区域 OCR。确认结算后按「停止策略 → 结束保护范围 → 恢复菜单输入」的顺序收尾，只按一次 B 完成。

状态检查继续沿用 `check_battle_state` 和 `last_check_end_result`；完成与撤退分开处理。异常、超时、暂停和操作退出都停止自动战斗。成功次数沿用 `ChargePlanConfig.add_plan_run_times`，临时计划只更新内存，不改用户配置。实拍返回路径为「结算 B → 预设 B → 材料分类 B → 大世界」；每一步都先确认该画面的两处文字，最后确认大世界快捷手册模板，未知画面只等待。不实现重复挑战，也不处理未出现过的奖励弹窗。

本地入口 `tools/macos/run_combat_simulation.py` 默认运行单次完整流程，`--prepare-only` 只到出战页。它使用已有 Mac 实例配置，不修改输入参数；主线程只启动一次运行上下文并持续处理 Cocoa 事件，Operation 在工作线程执行，避免 OCR 或等待阻塞采集。结束、异常与中断都停止运行上下文并关闭资源。`--entry simulation` 可从已在模拟室的预设或出战页开始；默认从大世界经快捷手册传送。

## 原客户端与运行前准备

Mac 保留现有 PySide6 客户端、全部导航页面，以及一条龙原任务列表、顺序、启用状态和体力计划配置。单次挑战入口仅供流程联调，不新增正式的 Mac 模拟室应用。每个原任务逐步适配后直接加入原一条龙执行链。

原「一条龙运行」页右侧提供「准备游戏（检查并切换手柄）」按钮，只执行公共游戏会话入口，不运行任务列表、不消耗电量。正式开始也会显式执行相同准备步骤，不能仅因窗口已连接就跳过模式检查。同一次运行中的已适配子应用复用确认结果；停止后重新开始、控制器重连或切换控制器都会重新确认。缓存按 Mac 控制器的运行代数区分，不依赖异步事件到达顺序。

未适配应用仍可查看和配置，卡片标明「Mac暂未适配」，运行按钮置灰；不会自动删除任务或改写用户启用值。已启用但未适配的任务允许用户主动关闭；一条龙启动前列出所有仍启用的未适配任务并停止，不静默跳过。独立运行、游戏助手等原运行页使用同一能力检查；正式执行前再次拦截，避免直接调用绕过 GUI。当前只开放已适配范围的体力计划与单实例一条龙；多账号和结束后系统操作仍在运行前说明限制。Windows 沿用原行为。


## 本机策略与其他机器复现

本机验证选用 `config/auto_battle/Mac全配队通用.yml`，其中自动转向关闭、结算检测间隔为 0.1 秒。该实例配置受 Git 忽略，不随源码提交。其他机器须复制已有通用自动战斗配置，设置 `auto_turn_interval: 0`，并在原体力计划中选取该策略；尚未校准的自动转向不能直接使用。不要为了同步本机验证配置提交整个 `config/` 目录。


## 卡片编辑（2026-10-25）

预设卡片 A 打开操作菜单，默认焦点是“开始战斗”；先识别并下移至“编辑”才 A。随机怪物卡编辑页 Y 减少一张、A 增加一张、X 保存；每一步重新读取实际消耗，数量未变不连发。单卡与五卡保存后的消耗分别实拍为 20 和 100。原体力计划可以顺序配置五卡一场、单卡一场；每项胜利分别保存原配置的运行次数，不用调试键逐项推动。


### 电量不足后继续原计划

当原配置开启“跳过计划”且五卡电量不足时，保留该项未完成次数，仅在本轮标记跳过，回大世界后尝试后面已配置且电量足够的单卡计划。不自动更换副本、不补电量。余量不足任何后续项时正常结束并报告读数；关闭跳过选项时保持原有不足即结束行为。

预设页恢复直接进入卡片与电量核对，不在已打开的模拟室页面重复调手册。下一步以完整底部提示区内的固定文本识别，保留足够上下文，避免窄裁图把“下一步”拆成两个 OCR 文本而误判未知页。零电量代表帧和真实局部 OCR 检查保存在测试仓。

## 指定预备编队

当前编队仍可沿用，另外支持原 GUI 中配置的首屏六个预备编队。准备页调用[公共手柄选队](macos_predefined_team.md)，成功核对成员后才允许出战；自动战斗策略使用该预备编队保存的配置。公共组件已在恶名狩猎准备页实机通过，模拟室接线有针对性测试，今日电量耗尽后不为重测购买资源。


## 配置指定的基础材料（2026-10-26）

基础材料计划中的 mission_name 贯穿专项选择、卡片编辑、耗电检查和出战准备；调查、音擎、赏金、镀剂专项共用 GamepadChooseSimulationPreset。当前唯一黄框与目标文字一起决定方向，每步确认新帧；未知目标或焦点不操作。旧预设菜单先按已识别的 B 路径关闭，避免在弹窗中执行横向选择。

GamepadConfigureCards 接收目标专项和数量，菜单识别区域覆盖整条方案带，保存后重新核对专项与耗电。单场挑战发现上层已配置正确时只读复核，不重复编辑；若从出战页重新开始，先返回方案页确认材料。编队准备节点预算覆盖公共选队操作和配置间隔。

原计划不足并允许跳过时，会依次越过后面的高耗电项，寻找已配置且可运行的任务；不修改任务、卡数或完成次数。专项名称不一致即停止，不能用相同的 20/100 耗电替代目标核对。

生产单场操作提供显式 resume_from_battle 恢复入口，仅供已知本次目标和配置的中断战斗使用；它要求真实战斗 HUD 命中，不能与 prepare_only 同时使用。原 GUI 正常运行不自动选择此入口。恢复通过单独记录，不充作从大世界开始的无中断验收。


## 普通材料分类与跨页选择

四类普通模拟室材料共用已验证的基础材料手册入口，到达后由 GamepadChooseSimulationPreset 按 mission_type_name 和 mission_name 切换实际分类、专项，不能把传送入口当作最终材料选择。专项列表与排序读取原 CompendiumService 数据，分类转换先返回五卡分类页，再按整卡焦点进入目标分类。横向列表滚动后仍识别实际专项，未知焦点不确认。

卡数支持1～5，默认仍明确按5张；出战前实读消耗并要求等于卡数×20。原配置、次数和编队继续沿用，未解锁或数据中不存在的目标明确失败，不替换目标。卡片编辑过渡帧允许短暂等待；从已识别编辑页恢复时先返回方案，重新核对目标后再编辑，避免沿用不明编辑上下文。
