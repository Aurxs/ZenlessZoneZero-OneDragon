# Mac 最小储蓄补电

原体力计划显式选择`restore_charge: 使用储蓄电量`后，还需同一配置的`macos_reserve_date`（北京时间日历日）及`macos_reserve_limit`（1至320）。无日期、过期、无额度、电池或混合来源均拒绝。默认恢复“不使用”；许可结束删除临时日期和额度。

当前仅支持已完成五卡基础材料后的普通巡防余项；不支持循环、双倍、培养或其他补电类别。剩余预算从原真实次数计算，仅补本场60所缺，不超储备、界面上限或剩余计划。

流程：巡防不足详情→一次Start→来源全文、唯一储蓄焦点及三项余额→快捷使用准确差额及1至240范围→确认前原子写本机回执→一次确认→已知获得及电量增量→复用已完成百电基础预设只读余额（不出战）→对账后取消返回→原巡防继续。

本机`.debug/macos/reserve_<实例>_<日期>.json`的非verified记录跨进程禁止重领。自然恢复临近、未知来源/焦点/数量、截图保存失败、资源不等额或电池/菲林变化都停止；不删回执或手改状态。补电不增加胜利计数。

2026-11-01首例正式CLI：19补41至60，储备1406→1365，电池5、菲林948未变；完整核账后完成最后巡防并返回，两个原计划均2/2。34项预算及10项集成保护检查、同路径现场OCR回放和修改文件Ruff通过；仅证明该受限闭环。私有图片及日志只保留本机，不提交。页面事实见[恢复电量](../../../game/screens/恢复电量.md)。
