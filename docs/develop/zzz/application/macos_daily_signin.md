# macOS 手柄每日签到

每日签到继续使用原应用与 `selected_sign` 配置，一次只运行一个签到玩法。刮刮卡、卦象集录和吼吼饼铺共享每日同类奖励次数，不能依次运行来补齐三个项目。当前 Mac 实例按用户选择使用 `trigrams_collection`（阿朔占卜）；仓库默认值仍是吼吼饼铺。

Mac 分支由原每日签到应用委托 `GamepadDailySignIn`，不再进入 PC 子应用的坐标点击与拖动；Windows 保留原子应用代理。公共手柄地图传送负责抵达「澄辉坪 → 阿朔」，签到分支沿用原应用在落点直接交互的流程，不额外走动。

原流程依据见[卦象集录画面](../../../game/screens/卦象集录.md)：打开主界面、获取卦象、完成占卜动作、确认奖励并返回。手柄主界面标题和「占卜」提示同时存在、中央「開」模板命中时，只按一次 A 开始；「闭」封面表示已完成，即使底部仍显示「占卜」也直接进入返回流程，不能重复 A。公共传送确认到达后等待一秒，直接执行一次原有交互动作，再用主界面标题与占卜提示确认进入；不检查随镜头移动的 NPC 姓名位置，不追加移动。公共地图传送见[手柄地图传送](macos_transport.md)。

操作可从大世界、已打开的主界面或当前占卜进度恢复。实拍提示为「拨动右摇杆以获取卦象」，程序确认固定摇杆提示后，通过原控制器右杆方向键按「右 → 下 → 左 → 上」分段旋转。每段保持 0.25 秒后归零，连续十二段的持杆总时长为三秒；中途不做 OCR，每段前检查暂停和停止，仍沿用控制器的有效画面保护。整轮结束后才重新截图，优先判断结果与确认，否则提示仍在时再读进度。

百分数仅辅助观察进度，读不到数字不阻止三秒动作；截图时间未更新时不开始下一轮。进度倒退、连续三轮不增长、达到三轮或三十六段上限、节点超时都会停止；暂停、停止、正常结束和异常退出均释放右杆。2026-10-26 未领取状态下已由组件实际旋转两轮并出现奖励；当日结果确认修复后分段完成返回，不能写成首次无中断通过。PC 来回拖动没有用于该映射。

首次起点、主界面、各个新进度与未建档结果自动保存 PNG，返回结果的 `data.evidence` 提供绝对路径。优先处理前景奖励弹窗，避免把其后的结果页当成当前页面。奖励页要求「获得」标题、「选择」提示及确认按钮黄色填充同时存在；每次弹窗只按一次 A；奖励弹窗关闭后允许再次确认卦象结果，避免先出现的结果页消耗了后续确认机会。卦象结果须同时识别「确认」「解卦」及娱乐说明，再只按一次 A。程序不触发解卦或分享，确认回到已知主界面才按 B 返回大世界。主界面若变成未建档的「今日已领取」布局，也保留现场。动作后的短暂过渡只等待，连续三轮仍未知时停止并保存截图，不猜确认、不标领取成功。

正常入口只有在本次发出占卜摇杆后才接受通用「获得」弹窗。联调中已核实来源、需要从奖励或卦象结果页恢复时，显式传 `resume_from_reward=True`；恢复成功状态为「奖励恢复确认完成」，返回数据另外记录是否从大世界开始、实际发送的摇杆段数。恢复结果不能写成从大世界开始的完整实测。右摇杆动作与分段恢复证据见[迁移进度](../macos_migration_progress.md)，恢复数据不能替代首次完整运行数据。

「今日已经完成过一次相同类型的奖励领取」属于今日已领终点，确认操作必须按对应手柄画面补档，不能反复重新获取。

尚未建档的刮刮卡或吼吼饼铺选择会明确停止，不静默改成卦象集录。应用运行记录继续由原每日签到应用保存；单纯打开界面或发送一次确认不能认定领取成功。GUI 仅开放已经完成适配的卦象集录，其他签到方式仍明确提示未支持。

局部 OCR 验证直接使用实际平台区域、真实 OCR 服务和代表帧，不把全屏 OCR 的文字框当作局部识别结果。「占卜」提示覆盖整组底部提示，保留周围上下文；过窄的两字裁图会导致文字检测为空。开闭封面用原 PNG 经 `TemplateInfo` 分别生成模板，只有平台 patch 引用，PC 资源不变。
