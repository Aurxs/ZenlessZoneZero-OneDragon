# 影像店营业(自动化方案)

> 本文档讲**怎么自动化**影像店营业玩法(脚本流程 / config / 设计决策)。
> **玩法机制**见 [gameplay/影像店营业.md](../../../game/gameplay/影像店营业.md);**画面识别**见 [screens/影像店营业.md](../../../game/screens/影像店营业.md);**文档分工**见 [harness/doc_organization.md](../../harness/doc_organization.md)。

**自动化目标**:每日完成录像店营业(选宣传员 + 上架录像带 + 开始营业);已营业则跳过。

## 1. 玩法与自动化的关系

玩法机制详见 [gameplay](../../../game/gameplay/影像店营业.md)。脚本覆盖的子玩法及其自动化角色:

| 子玩法 | 游戏含义(详见 gameplay) | 脚本角色 |
|---|---|---|
| 选宣传员 | 派驻代理人影响营业 | 按 `config.agent_name` 选(OCR 名称优先 + 头像兜底 + 滚动) |
| 上架录像带 | 为 3 主题上架匹配录像带 | 主题 OCR + difflib 匹配 16 主题 + 上架筛选循环 |
| 开始营业 | 确认营业赚取丁尼 | 点开始营业 → 确认 → 营业后确认 |
| 已营业跳过 | 正在营业态 | `check_running` 检测 → 关闭经营页面 → 返回 |

## 2. 脚本流程

主 app `RandomPlayApp` 节点链(详见代码 + [screens](../../../game/screens/影像店营业.md)):

1. `transport`(传送;对话或经营画面加载失败时重试)
2. `move_and_interact`(POINT_1/POINT_3 `turn_to_angle(0)`+`move_w` / POINT_2 直接 interact;sleep 1 + interact 0.2 防失效)
3. `handle_interaction_dialog`(交互对话;POINT_1 直接放行;其余入口优先点击「查看经营状况」选项,未命中时盲点对话框标题推进;不判断后续经营画面)
4. `wait_run`(等待经营画面加载;昨日账本关闭 / 经营状况点击)
5. `check_running`(正在营业→关闭经营页面;否则→选宣传员)
6. `choose_promoter`(已选「换下」→跳过;OCR 名称 + 头像匹配 + 滚动兜底 + 确认)
7. `check_video_theme`(识别 3 主题,difflib 匹配 16 主题)
8. `click_video_entry` → `check_recommended`(推荐上架→返回;上架筛选→上架)
9. `click_filter` → `choose_theme` → `choose_onshelf`(主题筛选 + 上架,3 主题循环)
10. `back` → `start`(开始营业)→ `confirm_business`(确认)→ `confirm`(营业后确认)
11. `back_to_world`(`BackToNormalWorld` 回大世界)

**设计决策(为什么)**:
- **POINT_2 推荐**:传送落点正对入口,直接 interact(POINT_1/POINT_3 需 turn+move,易出错)。
- **宣传员 OCR + 头像兜底**:名称 OCR 优先,失败用头像模板匹配(`predefined_team/avatar_`)。
- **主题 difflib**:16 主题 OCR + difflib 模糊匹配(主题名 OCR 可能不准)。
- **已营业跳过**:`check_running` 检测「正在营业」→ 关闭经营页面 → 返回(不重复营业)。

## 3. 支持配置(`RandomPlayConfig`)

- `transport_point`:传送点(POINT_1 录像店-柜台 / POINT_2 澄辉坪-录像店营业点 / POINT_3 布亚斯特城区-录像店营业点)。
- `agent_name_1` / `agent_name_2`:宣传员(代理人名;`RANDOM` 随机选)。

## 4. 注意事项

- **每日首次**:昨日账本弹窗(`wait_run` 关闭后再判经营状况,防残影 / 未关闭)。
- **interact 防失效**:`move_and_interact` sleep 1 + interact press_time 0.2(issue #2405 / #2395 / #2328)。
- **跨画面 op**:`transport`(Transport)+ `back_to_world`(BackToNormalWorld)跨画面。
- **营业确认弹窗待补**:开始营业-确认 / 营业后确认(画面 fixture 待拍)。

## 5. Mac 手柄分支

Mac 沿用同一个 `RandomPlayApp`、原运行记录及上述节点链，只将输入步骤分流到手柄操作。地图使用公共 `GamepadTransport`，入口对话使用 `GamepadChooseDialogOption`，不会转发 PC 坐标点击、鼠标滚动或拖动。

公共对话操作从[手柄对话选项带](../../../game/screens/对话.md)读取完整目标与唯一黄色填充行，再逐帧移动焦点。目标高亮且同排 A 提示存在时确认一次，保存确认前后截图。返回「已选择查看经营状况」只说明选项动作完成，后续 `wait_run` 仍须识别经营页或昨日账本；目标消失不能代替业务完成判断。

需要传送时，当前入口只接澄辉坪的录像店营业点。录像店柜台和布亚斯特城区仍缺少手柄转向移动依据，会在传送前说明不支持，保留用户所选传送点。应用已经处于昨日账本或经营主页时直接恢复原节点，不重传送、不再次交互；识别经营主页要求标题与营业状态同时存在，并排除宣传员和上架子页。

店内动作由 `operation/gamepad/shop.py` 登记已核实按键，并要求同帧命中 `手柄-<动作名>` 专属提示区域。昨日账本识别标题后，B 关闭一次并等待新帧；经营页进入原营业状态判断，正在营业继续走原跳过分支。未登记的动作、缺少提示或未知焦点均停止，不尝试 PC 点击。

宣传员保留原配置。含“随机”时确认当前黄框内的合法人物；指定人物仅接受已识别的当前焦点，跨页查找尚不支持。A 进入宣传员或录像带卡片、A 确定人物、X 推荐上架、B 返回均按实拍提示执行。X 推荐上架直接回到经营主页，不再按 B。营业前重新识别实际人物名、三片标题和三个主题的蓝色完成标记，缺少任一项不发送 X。逐主题筛选和未建档确认弹窗保留失败与截图；公共实测状态见[迁移实施进度](../macos_migration_progress.md)。

营业每天只有一次，营业后页面会变化。组件验收从未营业界面直接运行代码，不能先手动营业再只测试跳过分支。代码保存营业状态及确认操作前后的关键帧；操作前截图未写盘时不发送确认，动作后重新截图保存结果。同一消费节点记录已经发送的动作，异常重试不重复确认。未知状态先留图后停止，证据位于主仓 `.debug/images/Mac_影像店营业_*`，由日志输出实际路径。


### Mac 营业确认与恢复

手柄经营页按 X 后出现“是否准备营业？”弹窗，确认按钮黄色高亮，底部 A 选择。按 A 后显示“诚信经营，丁尼为本！”，再次 A 后回到大世界。生产节点分别核对完整提示和确认焦点；恢复执行时可从这两个明确弹窗继续，不重走传送或再次开店。对话 A 可能先补全台词，公共对话操作等新帧中原选项消失后才进入下一节点；同一完整选项与焦点仍可见时最多确认三次。

2026-10-25 实机已完成随机宣传员席德、推荐三片、营业确认和返回；详情见迁移进度。指定宣传员的列表移焦仍未支持，保持明确失败，不替换用户设置。


### 单按钮确认复用

营业成功祝词会变化。正常节点在已确认营业后调用公共 `confirm_expected_single_dialog`：只匹配居中黄色确认按钮与下方 A 选择图标，不 OCR 祝词，匹配后只确认一次。该操作仅用于调用方明确正在等待的结果弹窗，不是全屏见确认就按 A。双按钮询问页不匹配。中断后从未知起点恢复仍核对已建档的经营祝词，不能把其他确认框当作营业成功。
