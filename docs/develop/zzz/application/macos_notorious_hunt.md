# Mac 恶名狩猎迁移

目标是沿用原恶名狩猎应用、计划设置、周运行记录和自动战斗，通过新增手柄操作完成免费周期挑战、结算与奖励领取。Windows 流程和底层输入保持现状。

## 首轮范围

用户允许先选择适合当前编队的 Boss 验证，但正式入口从原计划读取副本、等级、增益、策略与次数，不写死联调目标。难度由用户在一条龙 GUI 的恶名狩猎设置下拉框选择并保存，Mac 新计划默认“最高可用等级”；该选项按游戏实际开放等级解析，不写死 Lv.65，也不要求用户到游戏里手动选择。已明确指定的具体等级保留。支持当前编队或前六个预备编队，复用共用编队操作；不支持的选项明确提示。以画面实际剩余奖励次数为准，耗尽后退出，不自动进入消耗电量的深度追猎。

## 实现顺序

1. 复用快捷手册的稳定标签、分类焦点和传送确认，扩展恶名狩猎入口及目标列表。
2. 用常态标题和按键提示确认挑战页，读取目标、难度和免费剩余次数。目标选择沿用上游副本数据与别名。
3. 转换增益选择、当前编队、出战、必要的战前移动和结算；复用已有自动战斗执行器与手柄输入保护，不能直接复用模拟室的电量扣减。
4. 成功结算后更新原计划和周记录；核对次数变化后继续或结束，领奖并返回大世界。失败不增加完成次数。
5. 完整组件实机通过后开放原 GUI 恶名狩猎卡片，单独配对提交。

已知起点下可执行短连招，保留动画等待，在分支、出战前和结果处确认；动态 Boss 名只用于匹配配置目标，不能作为通用页面识别依据。

## 验证边界

先验证一个目标的一场完整挑战，再补免费次数耗尽和周奖励返回。用户当前编队是否适合目标以实际战斗为准，不把模拟室通过当作 Boss 已验证。现场工具仅观察，由生产 Operation 执行游戏操作。已取得入口、难度下拉框、编队、接敌、引导和失败结果画面。首次失败已由生产操作退出，免费次数仍为 3/3。最高等级 Lv.65、叶瞬光编队的单场准备→接敌→自动战斗→结算→返回已实测成功，用时 43 秒，免费次数 3/3→2/3。周期 X 全领、A 确认获得、B 返回及双层返回街区已实测。原应用剩余两场串联正在验证。

后续顺序：恶名狩猎 → [体力自定义材料](../macos_daily_routine.md#下一阶段更换体力材料与副本) → 迷失之地周常。

## 直接复用原流程

战前接近目标采用原 NotoriousHuntMove 的模型、距离识别、移动和转向算法，通过 Mac 控制器适配执行。新增子类仅处理可选战斗引导；未出现时直接委托原方法。战斗策略沿用原自动战斗执行器，不另写固定攻击连招。官方距离模型已按 GitHub 发布资产 SHA-256 校验后下载，数据文件保留在忽略的模型目录。

## 单场流程与结果

GamepadNotoriousHunt 串行执行准备、出战、上游战前移动、上游自动战斗、结算退出。距离模型在进场前加载。Boss 血条使用移动端模板，模板素材按项目 RGB 约定保存；不能直接把 OpenCV BGR 图片传入素材保存接口。

结算必须同时识别“挑战结果”和“完成恶名狩猎”的 1/1 才算成功，0/1 为失败。退出后重新读取免费次数；只有比进场前少一次才更新原配置与周记录。失败不累计完成次数。

## 当前开放范围

GUI 沿用原恶名狩猎任务与计划卡片，难度默认最高可用，可选择具体等级。当前首个完整实测目标为库萨里库；其他 Boss、需要鸣徽选择的场景、深度追猎和预备编队第二页尚未开放，运行前明确提示，不替换用户计划。

周期领奖复用通用获得弹窗：标题确认后按 X 全领，获得弹窗按 A，按钮文字变灰并稳定两帧后按 B。入口返回需经过副本卡片列表，再返回街区；使用“当期剩余奖励次数 / 奖励详情 / 相关代理人”常态提示区分列表，不依赖 Boss 名。
