# Mac 预备编队选择

沿用原 TeamConfig、预备编队 GUI 和各计划的 predefined_team_idx。索引 -1 表示游戏当前编队，0～19 对应游戏二十个预备编队。

出战准备页 X 打开列表，复用原编队槽位和头像特征识别，核对配置成员与游戏成员完全一致。先以方向键首尾循环定位绝对行号，再逐帧核对黄色整卡焦点及相邻页四卡重叠。第一页向上会循环至最后一行，不能以按键次数猜页码。使用定位结果中的可见槽位核对目标成员；目标已经 SELECTED 时直接 Start 预备出战；否则选择后再确认。回到固定出战页面且无 EMPTY 空槽才完成，组件自身不发出战键。

原模拟室准备流程调用同一组件；指定预备编队时采用该队在 GUI 中保存的战斗策略，仍要求 Mac 策略关闭尚未校准的自动转向。恶名狩猎准备流程同样复用。失败不继续出战，不修改 Windows 选队操作。

本机按用户要求配置了前四队，分别以叶瞬光、仪玄、雅、蕾米埃尔命名，成员由游戏实拍和原头像匹配确认；配置保存在忽略的实例 team.yml，不提交用户配置。11:07 第一队确认、11:10 切换第二队、随后恢复第一队均由生产 Operation 执行，未进入战斗。第 3～6 队的导航使用相同网格规则，尚未逐队实测。

## 界面操作间隔

“设置 → 游戏设置 → Mac 运行设置（当前账户）”提供“界面操作间隔（毫秒）”，保存到实例 Mac 配置的 `menu_action_interval_ms`，默认 500，可设为 0–2000。所有手柄界面 Operation 经公共 `GamepadOperation` 在每轮步骤结束后至少等待此时长；原来更长的动画等待不缩短，也不额外叠加同样的延迟。配置每轮读取，下次界面步骤生效。组合键内部、摇杆连续动作和原自动战斗策略不拆开加延迟；两个自动战斗循环明确豁免。底层输入实现保持不变。

出战页切换动画可能吞掉第一次 X。打开预备编队时，仅在新的截图仍确认“出战 + 预备编队”时，每隔一轮重试，最多三次；列表出现后不再发送 X，避免把已打开的列表关回去。

## Mac 预备编队识别

遵循[手柄迁移开发约定](../macos_gamepad_workflow.md)，保留原 `PredefinedTeamChecker`、二十队编辑卡片及 `team.yml`。Mac 分支从功能导览进入管理页，只读扫描后返回大世界；原页面点击“预览并确认写入”才能保存。

### 行为

- 通过原定位器首尾循环确定第1队，再按方向键移动后的焦点与四张重叠卡片确认行号；管理页不使用“预备出战”或 SELECT 特征。
- 复用原头像识别。预览显示每队原名称、提议名称、原成员、提议成员及保留的战斗策略。RS 提示导致焦点队名漏字时，移开焦点后补读；仍未识别的队名保留。
- 成员不足三人时保留整组原成员，避免单个漏识别引起位置错配；空队也不清空原成员。策略与额外字段保留。用户确认后只写一次；账户、当前队名、成员或策略有变化时拒绝旧预览。
- 取消不写入，结果可再次预览；新扫描和账户重新加载会清除旧预览。结果仅保存在当前 GUI 会话，关闭后需重新扫描。
