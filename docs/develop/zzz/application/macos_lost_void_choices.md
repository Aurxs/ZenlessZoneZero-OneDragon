# Mac 迷失之地通用选择

`GamepadLostVoidChooseCommon` 负责手柄的鸣徽、卡牌与局中奖励武备选择，候选解析和优先级继续调用原 `LostVoidContext`。原任务接入和整链验收仍见[迁移进度](../macos_migration_progress.md)。

- 名称栏随卡片数量和类型改变。普通卡先定位实际黑色名称栏；双武备页使用原 GEAR 模板和武备名称区域。可选 `name_rects` 只限定识别范围，不改变原优先级；Windows 不传该参数时保持原区域。
- 单选先识别整卡黄色高亮，再移至原策略目标。普通鸣徽需要目标的“已选择”标记；双武备页无此标记，需要底栏 A 确定。提交后必须看到大世界或明确的下一交互，才返回父流程。
- 四候选多选使用各卡名称带，避免黑色名称条与正文连通后漏掉整卡。每次 A 后核对实际计数增加一和对应的新标记或黄色选中框；同流派文字会覆盖“已选择”，这时需要实际计数与完整选中边框相互印证，不能单凭同流派文字判断。候选未读全时等待，不按剩余片段做决定。达到目标数量、已选集合与计数一致且显示 X 确定时才提交；输入没有引起预期变化就停止，不重复盲按。
- A 确定的文字提示可由同排左侧的实拍 A 图标补充，匹配阈值 0.8；没有确定文字或同排图标时不确认，避免单字 OCR 漏检把获得提示卡住。
- 获得或升级提示按名称、等级区分连续页；变化连续两帧稳定后交回父流程，不能沿用上一批候选和已选状态。同一0项提示的A确定仅在新帧仍明确、等待2秒后有限重试，最多3次；不把信息弹窗的确认继续发送到后续选择页。

实拍归档在测试仓 `screens/迷失之地-通用选择/`：`ios_single_initial.webp`、`ios_multi_empty.webp`、`ios_multi_full.webp`、`ios_multi_same_style.webp`、`ios_two_gears.webp`。覆盖单选移焦、仅确认一次、多选候选完整性、计数无变化保护、同流派标记覆盖与双武备 A 提示检查；目前已分段实机通过。此组件通过不代表整局、8000悬赏或原GUI独立验收通过。

卡牌获得提示代表图为 `screens/迷失之地-通用选择/ios_gain_card_a.webp`。真实提示的 A 在 OCR 中漏检、模板匹配 0.84，生产 Operation 已确认后返回大世界；回归同时覆盖 A 缺失及出现在其他行的负例。

抽奖机奖励确认后可返回抽奖机，由其原次数判断决定是否返回大世界；通用选择不继续向抽奖按钮发送 A。
